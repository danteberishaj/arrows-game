## Decisions

1. **What a window is.** The brief's definition is circular: the set depends on the window's max target, and the
   window's length is the set's size. The set is always the top-k by capacity (membership is a threshold). I take the
   largest k whose k levels all fit the k-th capacity. Ties are never split, and at least two shapes are required,
   otherwise the pick throws rather than repeat or fall short.
   - Under the placeholder curve this is exactly the brief's set: 18 shapes, a fixed point (tested). No window is
     ever truncated.
   - **Where the set changes** (W3-14's rising curve): the window just before a rise shortens to end at the rise and
     deals the top-k shapes by capacity, each once. The alternative is to keep the full set and truncate the window
     (a random subset). That is a W3-14 choice, since the placeholder never exercises it. It is tested with synthetic
     rise and fall curves.
2. **The bag's `windowMaxTarget` is a parameter** (`(start, end) => number`, the brief's signature), with the
   placeholder as the default. Window caches are keyed by curve function identity. They only memoize: tests prove
   call-order independence and cold/warm equality.
3. **Bag seeds are reduced into 0..161803398,** `.NET`'s `MSEED`, because larger seeds are not exact in the JS port
   (Concerns 1). They are still namespaced: a two-round FNV with byte `0x62`. They are distinct from each other, and
   none equals `|seed(i)|` for i < 200,000 or `|dailySeed(d)|` for d < 20,000 (tested).
4. **v2 sizing is a separate `buildV2`,** a copy of the density-probe fit with a `V2_MAX_GRID_DIM` clamp.
   `buildFromShape` (shared by v1 and the daily) stays byte-untouched, so no v2 edit (W3-09, W3-11, W3-14) can reach
   a shipped board.
5. **The `__DEV__` assertion throws.** It reads `__DEV__` at call time and is false under node jest and tsx. Its
   positive control forces `__DEV__` and mocks the pick to Bolt; it then throws `Bolt 46x37 holds 202 cells at the
   clamp`.
6. **The cols-only clamp is counted, not proven.** The capacity argument covers "rows hit the clamp", because the mask
   is then the capacity mask. A wide shape whose cols clamp before its rows is guarded only by the assertion and the
   test, which asserts 0 cols-only clamps over 0–1999. None occurs under the placeholder. No v2 board reaches the
   clamp at all: EXECUTED `$SCRATCH/clampscan.ts` over levels 0–9999 gives max rows 43, max cols 44, 0 boards at 46
   and 0 shortfalls.
7. **The probe's clamp is per version,** and modes combine because the acceptance command combines two of them. v1
   output keeps every data row: only a version tag in the header and summary lines are added.

## Concerns

1. **Pre-existing, affects v1 and daily: `DotNetRandom`'s JS port is not exact for |seed| > 161803398.**
   - `.NET` wraps int32 overflow inside the seeding loop; the port does not. Draws from the third onward then leave
     [0, 1). The file's own comment ("all intermediate values stay well inside 2^31") is false for those seeds.
   - EXECUTED scans:
     - 5,333 of 20,000 campaign seeds have out-of-range state.
     - 4,651 of 20,000 draw outside [0, 1) within 50 draws; draw values reach −10.8 and +12.1.
     - Draws 1 and 2 were never out of range: 0 of 1,000,000 campaign seeds and 0 of 2,000,000 random seeds.
     - Seeds ≤ MSEED gave 0 bad streams in 200,000 × 1000 draws.
   - v1 is safe from crashes: `pick` and the target are draws 1–2, and `fillMask` tolerates bad draws. But `fillMask`'s
     randomness is skewed for about a quarter of levels.
   - v2's target is draw 1, so it is safe (tested: every v2 target lies in its band for 0–1999). v2's `fillMask` has
     the same skew.
   - Fixing the port changes v1 boards, so it is frozen. A v2-only exact RNG is possible while v2 is dark. That is
     an owner/controller call (question 3). Not fixed here.
2. **Performance.** See Timing: an aggregate +7.7% from content, a fatter heavy tail, and a one-time cold pick of
   about 130 ms (inferred). The owner's "nothing gets slower" rule is not met in the aggregate or on the cold first
   pick.
3. **The perf soak harness has no `--gen-version`.** W3-05 left this note: `soak-plan.ts` and `benchmark.mjs` still
   build v1 tap plans. A PERF build with `EXPO_PUBLIC_PERF_GEN_VERSION=2` now deals different boards, so soak taps
   would miss. This needs threading before any v2 device soak. It is out of this brief's Files.
4. **v2 content follows the live catalogue.** An appended shape (W3-18), a retirement, or W3-09's clamp re-deals
   every v2 window. That is fine while v2 is dark, but v2 must be frozen, with its own fingerprint, when W3-21 ships
   it. No v2 fingerprint is pinned yet (`04d0ec7e` is informational).
5. **Picture silhouettes now appear at Normal cell counts (260–400),** for example Crown 25×29 and Heart 22×22. In v1
   they appeared only at Super Hard sizes. Legibility belongs to W3-08, W3-19 and W3-22.
6. **Stale brief citations.**
   - `DESIGN.md:98-106` is now the "Shape by tier" bullet at about :160.
   - `levelGenerator.ts:65-66` is `:217-218`.
   - `shapeLibrary.ts:282` is `:264`.
7. **Files outside the brief's list:** `src/core/index.ts`, `scripts/analysis/shape-preview.ts` (F26),
   `generatorVersion.test.ts` (home of the retired test), `gameSessionLifecycle.test.ts` (a second copy of the
