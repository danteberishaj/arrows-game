### The product-code change (`src/ui/gameSessionLifecycle.ts`)

- **Why.** Spec Change 2: "Log generation time for the PERF level on device through
  `EXPO_PUBLIC_PERF_GEN_VERSION`". Generation runs in `createLevelSession` on the JS thread, and nothing
  measured it under Hermes. No harness can time it from outside: logcat timestamps would include
  rendering, and a Perfetto trace needs app sections.
- **What it does.** When `PERF_MODE` is true, `createLevelSession` reads `performance.now()` around the
  existing `LevelGenerator.generate` call. It then logs
  `[gen] index=… version=… arrows=… rows=… cols=… ms=…`. The generator call, its arguments and the
  returned session are unchanged. The V2-WIRE tripwire
  (`LevelGenerator.generate(...switchLevel` inside `createLevelSession`) still matches: `v1Floor.test.ts`
  passes.
- **Why it is inert in player builds:**
  1. `PERF_MODE` is `PERF_LEVEL_INDEX !== null`, and `PERF_LEVEL_INDEX` is null unless
     `EXPO_PUBLIC_PERF_LEVEL` is a non-negative integer at build time (`src/perfMode.ts`). No store or QA
     profile sets it.
  2. **Test:** "W3-15: a non-PERF build logs no generation line" (isolated module registry, env unset,
     `perf.PERF_MODE === false`, no `[gen]` line after a real `createLevelSession`).
  3. **Device, EXECUTED:** the normal set A build (`af9a4467`) was launched with logcat cleared and played
     into level 1. **0** `[gen]` lines, while the same process's `ReactNativeJS` log shows `Running "main"`,
     `[ads] … unitSet=test` and three `[capture-diag]` lines (the positive control that console output
     reaches logcat): `artifacts/W7-09/logs/normal-A-reactnativejs-after-play.txt`.
  4. **Honest limit:** the minifier does **not** remove the dead branch. The `[gen] index=` text is present
     once in the normal bundles (bundle grep `[1, 0]`). It runs only when `PERF_MODE` is true.
