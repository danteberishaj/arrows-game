## What changed

### `src/ui/firstPaintCleanup.ts`

- Added `FirstPaintCleanupTimer`, a small lifecycle coordinator with explicit `stage`, `committed`, and `clear` operations.
- `stage` supersedes older work but does **not** arm a timeout.
- `committed` arms the unchanged cleanup duration only for the currently staged ID.
- `clear` cancels the current timeout, optionally guarded by the flash ID.

### `src/ui/BoardView.tsx`

- Blocked-tap handlers now stage the tapped-arrow and blocker cleanups before setting their visible state.
- Layout effects report the committed `shaking` and `blocker` IDs. A layout effect runs after React commits the render and immediately before its first paint, removing the measured handler-to-paint latency from the lifetime.
- The existing ID checks remain in the state updaters, so a stale cleanup cannot remove a newer flash.
- A newer tap, successful removal of the shaking arrow, board replacement, and unmount still cancel the relevant cleanup.
- The same mechanism applies with reduced motion ON and OFF.
- `BLOCKED_BUMP_MS`, `BLOCKER_FLASH_MS`, both `+ 40` cleanup margins, curves, amplitudes, and colours are unchanged.

### Tests and audit pins

- `src/ui/__tests__/firstPaintCleanup.test.ts` proves that no timeout exists before commit, a newer blocked tap supersedes the older cleanup, and removal cancels cleanup.
- `src/ui/contrastAudit.ts` changes only the three `BoardView.tsx` source-line pins shifted by the added lifecycle code. The palette sites and expected roles are unchanged.

## Decisions

1. **Use a layout-effect commit signal.** It is the narrowest point after React has committed the visible flash and immediately before its first paint. It removes tap-handler latency without adding the extra rAF tail observed in the intermediate capture.
2. **Keep a small coordinator instead of duplicating timer logic.** Shaking and blocker lifetimes have the same staging/supersession invariant, and centralizing it makes the no-timer-before-commit rule directly testable.
3. **Apply the change to motion ON and OFF.** The cleanup lifecycle is shared, while the existing Reanimated curves remain untouched; the device capture confirms criterion 4.
4. **Retain exact existing durations.** No new timing number or owner-picked value was introduced.
