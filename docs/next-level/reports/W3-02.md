## What I implemented

Added three tests, plus their shared helpers, to the end of `levelGenerator.test.ts` (existing tests untouched, one new top-level import for `DotNetRandom`):

1. **`v1 corpus fingerprint`** — one FNV checksum (`checksumLines`, reused verbatim) over `shapeName`, `board.rows`, `board.cols` and every `arrow.toLine()`, for `LevelGenerator.generate(i)`, `i = 0..299`.
2. **`sweep(version, count)` helper**, called for `version = 1, count = 300` — one greedy pass per level that (a) asserts fill == mask, (b) asserts no cell overlap and everything in bounds, (c) greedily clears the board while counting removals in the same loop (no second O(n²) scan), and asserts removals === `arrowCount`. `version` is a plain `number` guarded by a runtime check (`!== 1` throws "not wired up yet") rather than a `1`-literal type, so a later task can add a `version === 2` branch without fighting TypeScript's dead-code narrowing on an unreachable literal comparison. I did not stub a v2 branch — that's the non-goal ("Any generator change") and would be inventing a generator API that doesn't exist yet.
3. **Per-shape fill+solve at rows 12, 24, 46** — mirrors the existing "every shape in every pool" test's structure, but (a) sweeps three row counts instead of one, with 46 being the generator's own upper clamp (the brief cites `levelGenerator.ts:65`, correct only at `da93dcd`; already `:73` at this task's own base `e7e3b38` because W3-01 landed first — see "Fix round 1" item 2), and (b) computes `cols` with the generator's *actual* sizing math (`roundHalfToEven` + `clamp(_, 4, 46)`, both copied verbatim from `levelGenerator.ts` since they're unexported) instead of the older test's coarser `Math.round` approximation — per the brief's "cols computed as the generator computes them."

## Decisions (routine judgment calls, recorded per instructions)

- **`sweep`'s `version` parameter type:** used `number` + runtime guard instead of a `1 | 2` union, since 2 doesn't exist yet and typing it in would either be dead code (TS flags `x === 2` as unreachable against a `1`-only union) or require inventing a `LevelGeneratorV2` reference that doesn't exist. A future task widens the guard and adds the v2 branch.
- **Where to compute the frozen checksum:** computed it twice for cross-checking — once against a real git worktree checked out at `da93dcd` (isolated, no code from later commits reachable), and once against current HEAD — see Verification #1. Both gave `d01abbd8`. I did not check the worktree calculation into any script in the repo; it was a throwaway `tsx` script run from the scratchpad and discarded.
- **`node_modules` for the `da93dcd` worktree:** rather than reinstalling deps in a second worktree (disk is tight — 4.9 GB free at Phase 2 start, under the 5 GB native-build gate), I symlinked the main repo's `node_modules` into the worktree. This is a JS-source-only exercise (the imported chain — `levelGenerator`, `shapeLibrary`, `boardLogic`, `arrowPath`, `difficulty`, `direction`, `dotnetRandom` — has zero external package imports), so this doesn't affect the computed values; it only saves disk. The worktree and symlink were removed after use (`git worktree remove --force`); `git status --porcelain` is clean apart from the intended test-file edit.
- **Wall-time comparison scope:** brief says "the commit message records the `npx jest` wall time before and after." I measured `npx jest src/core/__tests__/levelGenerator.test.ts` (this file only, not the whole 23-suite run) before and after my change, since that isolates the cost this task adds.
