## Decisions

1. **No flag.** The brief and W5.md classify this as a defect fix with no flag; the controller's flag note names new
   player-visible behaviour. The perf gate's "ON vs OFF" is run as FIX vs the HEAD bundle, with FIX again as the null.
   If the controller wants it flagged, it is a one-line gate around the slot.
2. **The digits are anchored `top: 0, right: 0` instead of filling the slot (`left: 0, right: 0`).** They keep their own
   measured width, so a sub-pixel rounding of the slot (Yoga rounds a `View` edge to the pixel grid, a `Text` width
   up) can never make a fill-width text box wrap its last digit. `textAlign: 'right'` is kept as the brief asks. The
   ghost is the first in-flow child, so the slot's baseline is the ghost's; both texts share one style.
3. **The counter row is one accessible element** (`accessible` + `accessibilityLabel={`${remaining} left`}`), so a
   screen reader still reads "60 left" once, as the single `Text` did, instead of "60" and "left" as two stops. It also
   keeps `uiautomator`'s counter read working (content-desc "60 left").
4. **The 30-tap and boundary taps use an offline plan from the HEAD generator** (`scripts/planlevel.ts`, from POLISH-T10
   `plan.ts`), with the tap on the arrow's on-screen cell nearest its middle (a cell centre lies on the arrow's own
   centreline, so the nearest-ink hit test picks it).
5. **`pace503.mjs` = POLISH-T10 `pace.mjs` with the counter reader widened** to `text|content-desc` matching
   `/^\d+ left$/` (the diff is 3 lines, printed in the build log). Everything else is unchanged.

## Concerns

1. **The header already overflows at 360 dp for long shape names; the slot adds up to 3.0 dp.** EXECUTED pixel
   measure (`cap/header-360x780-geometry.txt`), index 119 at 360x780 dp: the hint button's right edge is **8.0 dp past
   the screen edge on BASE** and **11.3 dp on FIX** (the ghost "222" is 3.0 dp wider than "144", computed and measured
   +9 px). The button stays tappable (74 of its 108 px are on screen). This is pre-existing and outside W5-03 (a header
   layout change is a non-goal here); it matters for W5-06 and any header task. A narrower ghost is possible (the widest
   numeral ≤ the arrow count, e.g. "122" for 144 arrows: +0.7 dp instead of +3.0 dp), but it needs a digit-advance table
   in the app and deviates from the brief's `WIDEST_DIGIT.repeat(…)`, so I did not do it. W5-06's header badge, when ON,
   removes this overflow for Butterfly (the hint button then ends on the 16 dp padding line; W5-06 report).
2. **Font scale 1.3 at 360 dp was not captured** (the brief asks 1.3 at the native width and 360 dp at 1.0). Given
   Concern 1, the header at 360 dp and 1.3 will overflow further in both builds.
3. **UNVERIFIED-DEVICE:** iOS text layout and physical Android OEM fonts (the brief's own list).
