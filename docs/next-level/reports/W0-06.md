## What changed

**Instrument** (`8b6bfc2`)
- `src/ui/contrastAudit.ts` (pure; imports only `theme.ts`):
  - WCAG 2.x `relativeLuminance`, `contrastRatio`, `composite(fg, alpha, bg)`, HSL conversion and `solveLightness`.
  - `USAGES`: 38 rows × 2 palettes = 76 gated rows. Each row is `{ id, fgRole, fgAlpha?, bgRole, sizePx, weight, kind, site, sizeSite? }`.
  - The gate is derived from `kind`, `sizePx` and `weight`: large text is ≥ 24 px, or ≥ 18.66 px bold, and SemiBold counts as not bold.
  - Deliberately excluded, with a comment in the file:
    - `AdHost`, which is `__DEV__`-only.
    - The emoji glyphs 💡 and ☀, which no token reaches.
    - The inactive Continue fill edge, which WCAG 1.4.11 exempts. Its label is still gated.
    - The panel fill against its composited scrim. See concern 1.
- `scripts/contrast-audit.ts`:
  - Prints every row for both palettes with ratio, gate and PASS/FAIL, and exits 1 on any FAIL.
  - Prints the scrim rows as information only.
  - `--solve <role> <bg[,bg…]> <gate>` walks HSL lightness at the role's own hue and saturation (0.1-point steps) and prints the from/to hex and HSL.
- `src/ui/__tests__/contrast.test.ts`:
  - The maths is checked against WCAG reference values (21:1, `#767676` = 4.54:1, and `composite('#000',0.45,'#FFF')` = `#8C8C8C`).
  - A site check: each row's `site` line must name its `fgRole`, and its `sizeSite` line must read `fontSize: <sizePx>`. That check is what makes a reverted font size fail its row.
  - One test per row. On the instrument commit the 26 failing rows were `it.failing`.

## Concerns
1. **Composited-scrim rows are printed but not gated here.** The brief's orientation table lists "surface against the composited win/lose scrim" (2.90/1.21/1.16/1.14), and `USAGES` could carry them. But W5-05 (ruling W5-1) owns those rows, the `scrimWon`/`scrimLost`/`surfaceRaised` tokens, and the requirement that they fail on today's tokens. They cannot pass by `border` alone (Daylight won: a 3:1 hairline against the fill is 1.03 against the grey scrim). So the script prints them under "Information only, not gated here (W5-05 owns)", and `contrastAudit.ts` says why. W5-05 should add them as gated rows.
2. **One `accent` token could not satisfy the brief's "lightness only" for both named sites on Ink Night.** White 16-bold labels need accent luminance ≤ 0.183; the Hard tier on `bg` at 4.5:1 needs ≥ 0.203. So the tier label got a per-site role, `accentText` (hue and saturation of accent), and `accent` moved only L −0.2 for the buttons. `accentText` also fixes the Daylight perfect-run line (13 SemiBold on surface), because the Ink Night value was solved against both `bg` and `surface`. Side effect: the Ink Night streak line goes from `#A98FF8` (6.23) to `#8C70F6` (4.50), darker than before but passing. It is visible in `web/after/w006-win-night-after.png`. `heartText` was added for the same per-site reason (Daylight `heart` passes everywhere else).
3. **Two sites the brief did not name, both consequences of its own changes or of W0-02:**
   - The pressed header-button fill was `border`. Raising `border` would drop the pressed glyph to 2.56:1 on Daylight, so the pressed fill is now `heartLost` (`#DBD7ED`, close to the old `#E0DCEF` look; glyph 6.34 / 6.90). `heartLost` keeps its name but now means "inactive fill". It is also still used by the dev-only `AdHost`.
   - W0-02's disabled Continue (`heartLost` fill, `inkDim` label) measured 3.66 / 4.42. Walking `heartLost` would have made the Daylight fill identical to `surface`, so the fill is now `bg` (label 5.22 / 7.23). The disabled button reads as an inset well, lighter than the panel on Daylight and darker on Ink Night: `native/after/w006-lose-*-after.png`. This changes the look W0-02 listed for owner acceptance.
4. **DESIGN.md lines left stale on purpose** ("Change nothing else in DESIGN.md"):
   - `:70` "LEVEL N" 18 Bold
   - `:115` spent = `heartLost` at 0.85 opacity
   - `:130` sound glyph `heartLost` when off
   - `:227` pip dims to `heartLost`
   - (`:102` "LEVEL N in accent-light" is still true.) A follow-up docs pass, or W5's typography task, should update them.
5. **No gradle build.** All captures use JS repacks over the `da93dcd` gradle APK, the same method W0-03/04/05 used. W0-06 is JS-only and adds no native module (react-native-svg `Line` ships in the existing native svg package), so the repack exercises the release JS path. W0-07's gradle artifact should repeat the menu and header captures.
   - Disk was 5.9 GB at start and 4.6 GB at the end. Another session is using disk. No native build was run, so the 5 GB gate did not apply to repacks, but the next native build needs a re-check.
6. **Instrument limits.**
   - The script trusts the table's `sizePx`. Only the jest site check ties it to source (m2 shows that it does).
   - Tier-coloured rows were verified by ratio only. The captures are all level 1 (Normal), so the Hard and Super Hard label colours were not photographed.
   - The ☀ (Ink Night theme toggle) and 💡 are emoji, which Android paints in their own colours; no token reaches them.
7. **Brief line numbers have drifted** (for example `HeaderButton.tsx:35`, `GameScreen.tsx:209/308/395/467/504-508`). W0-02 to W0-04 changed these files. The described code matched, so nothing diverged.
