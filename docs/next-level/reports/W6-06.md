## What changed

1. `src/telemetry/levelAggregator.ts` adds the pure, plain-number `LevelAggregator`. It emits one
   `level_start`, aggregates exit/blocked/ghost/miss taps plus hearts, hints, and continues, emits
   at most one `level_end` per start, becomes inert after end, and retains session tallies for
   `session_end`. `appLevelAggregator` is the shared instance used by `GameScreen` and `App`.
2. `src/ui/BoardView.tsx` adds the optional `onTapOutcome` callback and emits exactly one outcome
   for each unlocked tap. A ref distinguishes ghost from miss without adding state, an effect, a
   memo, or a per-tap allocation. The W0-04b staged `FirstPaintCleanupTimer` blocked-tap cleanup
   remains unchanged.
3. `src/ui/GameScreen.tsx` starts/ends the aggregator at the real guarded branches, records only
   charged heart losses and earned hint/continue rewards, accepts campaign/tutorial/daily mode,
   and records Home/unmount as abandoned. Rewarded calls now name `hint` or `continue` placement.
4. `src/ui/ads.tsx` emits one `ad_request` and one `ad_result` for every rewarded call and every
   due interstitial call, including killed, not-ready, display-failed, dismissed, and shown paths.
   Rewarded completion also emits `ad_reward`. Existing W0-05 pacing and W0-02 readiness/init
   ownership remain in place; remote kill decisions still come from W6-02's `RemoteConfig`.
5. `App.tsx` adds the controller-required `Telemetry.configure({ disabled: PERF_MODE })`, installs
   the development console or timing-only memory sink, applies the telemetry remote kill bit,
   configures W6-05's session index and bucket, emits `app_open` and all `screen_view` transitions,
   maps future daily/gallery screens to game/menu, and emits `session_end` from a separate
   background listener.
6. `src/telemetry/telemetry.ts` accepts configured `sessionIndex` and `bucket` rather than putting
   zero placeholders into every envelope.
7. `scripts/perf/android/benchmark.mjs` forwards and records
   `EXPO_PUBLIC_PERF_TELEMETRY_TIMING`; its argument tests cover set, unset, invalid, fresh-build,
   and caller-APK configurations.
8. `docs/perf-telemetry-ab-2026-09-19.md` contains the preregistered 5 ms MDE, five alternating
   pairs, every p95 with frame reconciliation and scale read-back, direct timing, bundle-absence
   proof, and the required UNEVALUABLE verdict.
9. Tests were added/expanded for the aggregator, PERF suppression, envelope identity, ad pairing,
   killed ads, and benchmark argument forwarding. `src/ui/contrastAudit.ts` received only the
   mechanical source-line updates required after `GameScreen`/`BoardView` grew; all contrast
   values and roles are unchanged.

## Decisions

1. A shared singleton bridges per-level tallies in `GameScreen` to App's background
   `session_end`; the aggregator itself remains independently constructible and pure-testable.
2. The schema has no `simulated` field and F08 forbids a schema-version bump. Development fake-ad
   events therefore use an adjacent `[ads][simulated]` log tag instead of adding an event field.
3. `telemetryScreen` accepts future `daily`/`gallery` values now and maps them per F08 without
   widening the current App screen state ahead of those workstreams.
4. The PERF memory sink is bounded to one event and the direct-timer quiet window is 750 ms; both
   code values are marked `OWNER-PICKED STARTING VALUE`. PERF suppression keeps the sink empty.
5. Activity-background attempts did not unmount the React root. The deterministic PERF proof
   therefore logs from the game-subtree unmount reached through Home. Superseded root-unmount logs
   remain in the artifact directory and are not cited as proof.
6. The W0-04b blocked-tap cleanup path was not refactored. Telemetry emits immediately before the
   existing blocked visualization logic, leaving its staged cleanup timing intact.
7. `continuesUsed()` is called only after an earned reward exactly as required. Because the same
   brief also requires `end('out_of_hearts')` immediately on the accepted lost branch and makes an
   ended aggregator inert, the current out-of-hearts event is already final before a later
   continue can be earned. No second end/start or schema behavior was invented to resolve that
   upstream lifecycle tension.
