## Decisions and tradeoffs

1. `onRemoval(now)` returns whether it moved an active deadline. `GameScreen` only replaces the timeout when that result is true, so a hint already consumed or a canceled/null timer cannot schedule a no-op follow-up.
2. The pure timer owns one-per-deal state; React owns only the single timeout handle. This keeps clock behavior unit-testable and lifecycle cancellation explicit.
3. The stall branch reuses the existing `hint` state contract exactly. It intentionally does not increment rewarded-hint telemetry and never reaches `Ads`, because this is tutorial assistance rather than a rewarded action.
4. The capture delay is only a **TEST VALUE**, not a recommendation or product value. The tracked code stayed `null`; W1-09/W1-11 own measurement and owner selection.
5. Updating `contrastAudit.ts` was required by its source-line integrity test after inserting lines in `GameScreen.tsx`; all audited semantics stayed unchanged.
