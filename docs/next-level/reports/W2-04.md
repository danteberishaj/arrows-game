## Decisions

1. **Flags per amendment**: `META_LEVEL_TRANSITION` in `featureFlags.ts`; the flags test is `src/__tests__/featureFlags.test.ts`
   because no existing test covered the defaults-OFF rule for all flags (it enumerates every `META_*` export, so W2-05's
   `META_PANEL_MOTION` is covered once added).
2. **Benchmark mode is routed through the scrim too** (flag ON), otherwise the AC11 soak would measure nothing.
3. **Panel beat after a shown interstitial (AC10 fix).** First capture (`real/nextad`, pre-fix build): the cover started when the
   SDK's closed event resolved the show, while Android's ad-activity exit animation (~185 ms, frames 151–163) was still revealing
   the game — the panel was never fully visible before the scrim rose (FAIL, `real/prebeat-ac10-montage.png`). Fix without touching
   `ads.tsx`: `awaitAdThenPanelBeat` detects "an ad was shown" (the app left the foreground during the show, or the show lasted
   ≥ `AD_SHOWN_MIN_MS` for the in-app `__DEV__` ad), waits for AppState `active`, then holds `PANEL_BEAT_AFTER_AD_MS`; the Next button
   stays disabled (`adBusy`) through it. No ad -> no delay.
4. **Covered state has no time backstop.** "Uncover never before `contentCommitted()`" is literal; the commit is guaranteed by
   React once `onCovered` ran, and if `onCovered` throws the sequencer uncovers anyway (tested). A lost commit would leave the screen
   opaque (not observed; INFERRED impossible short of a React failure).
5. **Backstop/AppState ends snap the scrim to 1 before the swap**, so a forced end never swaps behind a partly transparent scrim.
6. **Re-entrancy guards**: a Next pressed while a transition or its ad runs returns before any ad request; Continue is ignored
   while a Retry transition runs (a race the OFF code does not have, because OFF has no in-between frames).
7. **Retry analysis**: the old and new Retry frames share board and LEVEL text; the classifier decides on the discriminative
   pixels only (panel, heart pips) and reports AMBIGUOUS rather than guessing.

## Concerns

1. **HOME during the cover -> the system's return animation cross-fades the OLD panel into the NEW board for ~100–200 ms.** On
   return, Android shows the task snapshot taken when HOME was pressed (the old panel, partly covered) and cross-fades it into the
   live app (frames 46–53 of `cap/on-home-mid-cover-80ms`, `montage-return.png`). This is window-manager composition, not app
   content (the live app is already on the new level with the scrim uncovering); with the flag OFF (`off-home-80ms-control`) the
   swap is done before HOME and the snapshot is the new level. It only happens when HOME lands inside the ~300 ms transition. AC7's
   letter passes; the owner should judge it from the montage. Mechanism of the snapshot timing: INFERRED.
2. **Reduced motion gives a ~33 ms flat blink** (2 flat frames, `on-next-reduced`) instead of a hard cut: the instant cover, the JS
   swap and the one-frame wait. Alternative if unwanted: bypass the scrim when reduced motion is on (owner call).
3. **Cover-leg frame gap**: in `real/fit-on-final/next.mp4` one 56 ms gap (frames 184 -> 185) inside the cover. Single occurrence on
   a loaded emulator; not seen in the PERF captures (median 16.6–17.1 ms). UNVERIFIED-DEVICE.
4. `SCRIM_BACKSTOP_MARGIN_MS = 85` is an emulator measurement; a slower phone generates the 250-arrow board more slowly, but the
   cover backstop only matters when the animation callback is lost (the block happens after `onCovered`), so a slow device ends
   early only in that failure case. UNVERIFIED-DEVICE.
5. iOS not built or run (Reanimated/AppState behaviour there UNVERIFIED-DEVICE). Web preview not run.
6. The `GameScreen.levelTransition` UI test was written after the implementation.
