## Decisions and tradeoffs

1. `LevelSession.mode` is the single source for aggregator mode at every start. This makes campaign/tutorial ownership explicit now and leaves W4's future daily extension local to session creation.
2. Tutorial terminal callbacks reuse the existing guarded delay machinery. Phase stays `playing` while `terminalPending` locks the board, so no tutorial panel can render before re-deal/advance.
3. Tutorial progress is written after the transition is accepted and before its delay, matching the brief's crash-safe ordering without starting campaign stats.
4. The T1→T2→real and loss re-deal remain hard cuts. That is the explicitly accepted W1 state; W2 owns transition treatment and delay constants.
5. The tutorial header adds only an 18 pt override to the existing level-label style. The flags-OFF 24 pt level header remains byte-for-byte visually unchanged below the status bar.

## Concerns

1. The exact Expo dev-server form could not run under this managed macOS sandbox. The static Expo web export exercised the same compiled flag-on app and real browser storage, but it is not evidence for dev-server/HMR behavior.
