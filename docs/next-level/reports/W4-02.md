## What changed

- `src/core/streak.ts` adds the pure `advanceStreak` and `readStreak` rules. With the flag OFF they
  reproduce the shipped arithmetic. With it ON they spend enough freezes to cover all missed days,
  preserve the bank when it cannot cover the gap, handle a backwards clock without spending, and
  earn one freeze on positive multiples of 7 up to a cap of 2.
- `src/core/saveSystem.ts` adds the injectable `useClock`, public local-day `today`, bounded
  `streakFreezes`, pending `streakSavedDay`, and its clear operation. `dayStreak` and
  `registerSolve` now delegate their day-chain arithmetic to the pure rules. A rescue writes the
  existing P-01 key `arrows_streak_saved_day = today`.
- `src/featureFlags.ts` adds the controller-amended env-driven flag.
- `src/ui/HomeScreen.tsx` captures the whole stats string in `useState` on mount. With the flag ON,
  a non-zero pending saved day appends `   ·   streak saved` to that existing Text element and an
  effect clears the pending key. A theme rerender keeps the captured text; the next mount does not.
- `src/core/__tests__/streak.test.ts` covers every rule row and runs the same state table through an
  old-formula oracle when the flag is OFF.
- `src/core/__tests__/saveSystem.test.ts` drives gaps 0, 1, 2, 3, and negative through a real
  `SaveSystem` store with an injected clock and asserts the stored day streak, last day, freeze
  bank, and pending saved day.
- `src/ui/__tests__/storage.test.ts` contains the F13-amended cold-start case. It never touches the
  29-key exact-array assertion.
- `src/ui/__tests__/HomeScreen.streak.test.tsx` covers no streak at one solve, exactly one saved copy,
  persistence through a theme rerender, consumption, and absence on the next mount.
- `src/ui/contrastAudit.ts` only moves its seven HomeScreen source-line references to the same
  colour and font-size sites after HomeScreen gained ten lines.

No P-01 registry value, persistence-key array, schema version, or reset set changed. The two keys
were already registered by P-01. Migration is therefore additive/absent-key-default only: existing
chains are not rewritten at boot, and flipping the flag OFF leaves banked freezes inert. There is no
new wipe risk.

## Decisions

1. `useClock` returns the previous function, matching `useStore`, so tests and later W4 consumers
   can restore scoped clocks without a separate reset API.
2. Enabled-mode freeze reads are bounded to integer `0..cap`; disabled mode bypasses normalization
   so the old arithmetic and inert stored value are exact. An insufficient bank is never partially
   spent.
3. HomeScreen captures the complete string in the state initializer, while clearing happens in a
   mount effect. That satisfies theme-toggle stability without changing persistence during render.
4. The capture states were seeded at the real AsyncStorage SQLite boundary. The arithmetic that
   produces those states is independently exercised through `SaveSystem` with the injected clock.
5. Final APKs were JS-only Hermes repacks of P-02's release native host; no Gradle/native build ran.
   Bundle inspection found `META_STREAK_FREEZE = true` in the ON bundle and `false` in the OFF bundle.

### 1 — risk wording corrected (documentation only)

The two paragraphs above ("No P-01 registry value..." and the flag-OFF captures) already state
flag-OFF is byte-identical to da93dcd and that the freeze protection is flag-gated, but the
original wording in the "What changed" and capture-summary prose did not say plainly enough that
the backwards-clock and restored-backup protections **only exist when the owner flips the flag
ON**. To close this cleanly: flag-OFF behaviour (backwards clock, restored/rolled-back backup,
westward travel) is byte-identical to `da93dcd` — the reviewer's own EXECUTED finding (30-day
chain, `today = T-1, lastPlayDay = T`, flag OFF advances to `{streak: 1}`, matching the pre-W4-02
formula; the same chain with the flag ON advances to `{streak: 30}`). The freeze/rescue rows in
the brief's risk table are correct only for the flag-ON column; with the flag at its shipping
default (OFF), none of those protections are present and the day-chain arithmetic is exactly the
pre-W4-02 code path. This paragraph is the correction; no other section of this report claimed
otherwise, but none stated it this plainly either.

### 2 — corrupt-freeze clamp test rows added

Added a `describe('corrupt store freeze values clamp to 0..cap before use (freezes enabled)', ...)`
block to `src/core/__tests__/streak.test.ts`, three rows: stored freezes `-3`, `NaN`, `999`, each
run through `advanceStreak` from a first-ever solve (`lastPlayDay: 0`) so the resulting `streak`
of 1 is not a multiple of `earnEveryDays` (7) and `earnFreeze` passes the clamped bank through
unchanged — the output `freezes` field is exactly `boundedFreezes(storedFreezes, cap)`.

- **EXECUTED:** `npx jest src/core/__tests__/streak.test.ts --runInBand` — 1 suite / 25 tests
  passed (22 before + 3 new). The three new rows measured `-3 → 0`, `NaN → 0`, `999 → 2`,
  confirming (not assuming) the reviewer's numbers.
- No production change was needed — `boundedFreezes` in `src/core/streak.ts` already implements
  this clamp (`Number.isFinite` guard, then `Math.min(cap, Math.max(0, Math.trunc(freezes)))`),

### 3 — HomeScreen flag mock made robust

**Decision (deviation from the brief, documented per GLOBAL.md "stay inside the brief... say so
with evidence"):** the brief named the env-var + `jest.isolateModules` pattern from
`src/core/__tests__/saveSystem.test.ts:313-354` ("W4-02 SaveSystem day-chain wiring"). Applied
literally to `src/ui/__tests__/HomeScreen.streak.test.tsx`, this broke rendering:
`jest.isolateModules` forks the *entire* module registry, so the freshly-required `HomeScreen`
picked up a second, separate copy of `react` from the one `@testing-library/react-native`'s
`render()` uses (that library registers global Jest hooks at module load, so it cannot itself be
required inside a running test — `render` had to stay a top-level import). HomeScreen's own
`useSafeAreaInsets()` then read a null dispatcher from its own `react` copy that the renderer never
initialized.

- **EXECUTED (RED, confirms the brief's literal pattern does not work here):**
  `npx jest src/ui/__tests__/HomeScreen.streak.test.tsx --runInBand` with the isolateModules
  version failed both tests with `TypeError: Cannot read properties of null (reading
  'useContext')`, thrown from `react-native-safe-area-context/jest/mock.tsx:35` inside
  `HomeScreen` — the fresh-`react`-copy diagnosis above, not a flakiness or ordering issue.
- **Fix applied:** replaced `jest.mock('../../featureFlags', () => ({ META_STREAK_FREEZE: true }))`
  (whole-module replacement) with
  `jest.mock('../../featureFlags', () => ({ ...jest.requireActual('../../featureFlags'),
  META_STREAK_FREEZE: true }))` (spread the real module, override one export). This reaches the
  brief's actual goal — only `META_STREAK_FREEZE` overridden, the other three flags reading their
  real values — without forking the module registry, so there is exactly one `react` instance and
  hooks resolve normally.
- **EXECUTED:** a throwaway test (`src/ui/__tests__/flagcheck.test.tsx`, created, run, and deleted
  in this fix round — not part of the committed diff) applied the same `requireActual`-spread mock
  and logged all four flags:
  `CONSENT_GATE false REMOTE_KILL_SWITCH false TELEMETRY_TRANSPORT false META_STREAK_FREEZE true`.
  This confirms the three other flags read their real compiled values (`false`, not `undefined`)
  while only the target flag is overridden — the exact defect the brief asked to close.
- **EXECUTED (GREEN):** `npx jest src/ui/__tests__/HomeScreen.streak.test.tsx --runInBand` — 1
  suite / 2 tests passed with the `requireActual`-spread mock.
