## Concerns

1. **Brief command vs the Expo CLI (`--device emulator-5556`).** `expo run:android --device` matches the device **name**, and the serial is not accepted. `getDevicesAsync()` listed `{pid: "emulator-5556", name: "fleet_floor_api31"}` plus a non-booted `Pixel_8_Pro`, and `resolveFromNameAsync` does `device.name === name`. I passed `--device fleet_floor_api31`, which resolves to serial `emulator-5556`. All adb calls used `-s emulator-5556`.
2. **Release `expo run:android` builds all four ABIs by default.** `getConnectedDeviceABI` returns `''` for non-debug builds. I set `ORG_GRADLE_PROJECT_reactNativeArchitectures=arm64-v8a` so the APK size compares with the arm64 base and disk stays bounded. The command is otherwise as the brief specifies.
3. **`expo run:android --variant release` leaves Metro running** after install. I killed it before the capture, so the embedded bundle was what ran.
4. **Emulator radios were off when I found them.** I switched them on only for the capture and restored them afterwards. With the radios off, LevelPlay init fails on every build (error 2070), so any later task that needs LevelPlay init must enable them and read the state back.
5. **UMP was not given a workaround build.** After the Usercentrics build, free space was 5.2Gi, under the 7 GB gate. The brief also bounds the spike to two candidates. Whether UMP can work on this stack (Kotlin bump, older wrapper, or a UMP-only module) is still open. It matters because UMP is free and LevelPlay reads it natively.
6. **Base APK comparability.** The base was built at `a1e2b43` and the candidate at `d3f3a92` plus the CMP, so the +828720-byte delta includes P-01, P-04c and P-05 app changes. It is an upper bound for the CMP alone.
7. **Public repo.** Usercentrics' `status().location.countryCode` is redacted in the committed doc. The raw logs stay in gitignored `artifacts/`.
