**RULINGs**
1. **Stay, don't pop.** The spec says "unmount at phase change"; the rulings doc warned that pops the outline off as
   the scrim starts. The outline is **kept** under the panel until the board is replaced (Next / Retry). Chosen over a
   fade-out with the scrim: it needs no second animation, the scrim dims it exactly like the rest of the board, and
   the panel's own badge echoes it. Measured: it is still drawn, at the scrim-dimmed contrast, 10 s after the panel.
2. **The reveal implies W2-06's timeline.** Set B is defined on W2-06's "exit + hold + reveal" schedule, so with the
   reveal flag on the panel uses it even if `META_POST_CLEAR_TIMELINE` is off. With neither flag: the flat 450 ms.
3. **No outline, no slot** (the rulings doc's proposal, extended): the 400 ms is spent only when an outline is drawn.
   Reduced motion (nothing mounted) and tutorial boards (empty mask) wait exit + 250 ms.
4. **Look:** the play area's `accent` (the skin tint changes only `bg`), stroke = max(the arrow stroke, 2 pt on screen)
   (2 dp is the q3 mock-up's stroke; OWNER-PICKED STARTING VALUE), round joins, fade-in `Easing.out(quad)`.
5. **Tap clock:** on the device the overlay node mounted 93-262 ms after the tap (React commit under host load). A
   delay counted from the mount squeezed the outline's slot to ~250 ms in the first build (`b3on-w517-v1`), so the
   delay is now counted from the tap; a node that mounts after its start time fades in at once.
6. **"4x" capture** = the normal-speed recording rendered at 4x slow motion (as the rulings mock-up did), not an
   animation scale of 4.
7. **Board:** level index 0 (Circle 20x20) for registration and timing, not the spec's index 167 (a 202-tap solve per
   run under host load 40-226). The registration method does not depend on the board.
8. `EMPTY_BOARD_HOLD_MS` = 250 also applies to `META_POST_CLEAR_TIMELINE` alone (set B's pause).

**Reconciliation against 0.74-0.84 s.** The app schedules the panel at exactly exit-visible + 250 + 400 ms in every run
(the logged `wonDelayMs`). The owner's 0.74-0.84 s assumed W2-06's exit range of 90..187 ms, which was measured with
`META_EXIT_TO_SCREEN_EDGE` on (every test build). With it on (B3edge), level 1's final exit is 187 ms → planned
**837 ms**, measured 886 ms from the clear handler and 930 ms from the tap in the one run without a host stall: the
plan plus 44 ms input→JS and 49 ms timer lateness. With `META_EXIT_TO_SCREEN_EDGE` off (the player default today,
B3on), the same exit is the board-edge trail of 244 ms (`exitTrailDurationMs` 180..320), so the panel is planned at
894 ms (measured 907-918 from the handler in the clean runs), and the range is **0.83-0.97 s**, not 0.74-0.84 s. The
extra ~0.1 s is the last arrow's own slither, not the pause or the outline. **This is a finding for the owner, not a
W5-17 defect:** if 0.74-0.84 s must hold without the screen-edge exit, the pause or the outline slot has to shrink.
The lag over plan is the same in OFF runs (+36, +312), so it is host load, not the reveal. Resolution: logcat
monotonic prints 1 ms; input eventTime 1 ms; a JS timer fires on a frame (16.7 ms).

  divided by the scrim's own darkening, is 0.68-0.74 at the last frame (the rest of the outline is under the panel

- **Census (W5-19's rule):** the won panel's uiautomator tree is identical OFF and ON (51 nodes, the same 13 strings,
