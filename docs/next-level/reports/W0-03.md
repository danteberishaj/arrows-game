## What changed

`src/ui/splashBackstop.ts` (new, pure TS)
- `createSplashBackstop({ maxMs, now, setTimer, clearTimer, onDone })` returns `{ finish(), onAppStateChange(state), dispose() }`.
- `finish()` calls `onDone` at most once and clears the timer.
- Construction records `mountedAt = now()` and starts a `maxMs` timer that calls `finish()`.
- `onAppStateChange('active')` calls `finish()` when `now() - mountedAt >= maxMs`. No other state finishes it.
- `dispose()` clears the timer and closes the object. After that, no path reaches `onDone`, including a timer callback that was already queued.

`src/ui/SplashScreen.tsx`
- `export const SPLASH_MAX_MS = 4000; // OWNER-PICKED STARTING VALUE`. The comment gives the 2630 ms floor from the file's own timeline.
- One backstop is created per mount, in the same effect as an `AppState` subscription. Cleanup removes the subscription, disposes the backstop and clears the ref.
- Both `runOnJS(onDone)` sites are now `runOnJS(finish)`, where `finish` is a stable callback that calls `backstopRef.current?.finish()`. `onDone` is read through a ref, so the latest prop is always used.
- The healthy animation is unchanged (no timing or value edits).

`App.tsx`
- `const [fontsLoaded, fontError] = useFonts(...)` and `fontsReady = fontsLoaded || fontError != null`.
- `initSaveSystem().then(...).catch(() => setReady(true))`. A comment explains why there is deliberately no timeout.

`src/ui/__tests__/splashBackstop.test.ts` (new): 10 cases.

Nothing else changed: no persistence keys, no ads code, no splash reduce-motion treatment, no font timeout.

## Concerns
1. **No gradle build: the disk was below the gate.** `df -h /` showed 4.6 GiB at the start, under the 5 GB gate. Capture APKs are debug-signed repacks: a release Hermes bundle over the gradle-built base APK. For JS-only changes this is equivalent. The pipeline's bytecode fidelity was shown in W0-02, and the healthy control here reached the menu. Still, the brief's "release build recipe" was not literally run. W0-07's single-artifact verification should repeat criterion 2 (five cold starts) on its gradle build.
2. **Injection 2 as written in the brief does not reach the platform font.** "Make `useFonts` return `[false, new Error('injected')]`" still calls the real hook, so Fredoka still registers and the menu renders in Fredoka. That still proves the readiness gate. To prove the platform-font fallback, I added injection 2b (hook not called, so fonts are never registered). Both runs are recorded above. If W0-07 or later tasks reuse this injection, they should use 2b.
3. **Pre-fix severity.** No natural trigger for the stuck splash was reproduced: backgrounding mid-splash on the base APK recovers. The splash backstop fixes a by-construction defect. The font and save-init parts fix states that only injections reach.
4. **Evidence path.** `artifacts/W0-03/`, per the controller brief, not `artifacts/w0/W0-03/` as the W0.md header says (same as W0-01 and W0-02).
5. **Emulator state left behind.**
   - emulator-5556 has the debug-signed `final-453ea9a` repack installed. Its data is the root-seeded save (current level index 6, which the menu shows as "Level 7"; 6 solved; schema 1).
   - Scales are `1 1 1`, the radios were not touched, and the app is force-stopped.
   - A release-signed install over it needs `adb uninstall` first.
6. **Constant placement.** `SPLASH_MAX_MS` lives in `SplashScreen.tsx`, as the brief says, and is exported. The backstop module takes `maxMs` as a parameter and holds no picked number.
