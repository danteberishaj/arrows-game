## Concerns

1. **Two small API choices the brief did not fix.**
   - `Keys` is still module-level, but `SaveSystem.registeredKeys` exposes the frozen record. Acceptance 2 asks the test to walk `Keys`, which isn't possible without some export. Its doc comment says it exists for that test only.
   - `SaveSystem.setPersistenceHealthy()` is public, because `initSaveSystem()` lives in another module. It is documented as init-only, but nothing enforces that.
2. **A negative stored schema version is inert** (no write). The brief only defines 0, equal and greater. Treating corrupt data as untouchable matches the "never guess" rule; a reviewer may prefer a different rule.
3. **The core tests use a local `RecordingStore`** rather than the unexported `MemoryStore`. The characterisation tests had to pass on the unchanged code, which does not export `MemoryStore`. It has the same Map semantics, plus a delete log.
4. **`storage.test.ts`'s `beforeEach` now seeds `arrows_schema_version='1'` and settles the write queue.** This setup change is what keeps the existing batching tests seeing only their own writes. Their assertions are unchanged.
5. **Existing risk, outside scope.** After a failed hydrate, `HydratedIntStore` still sends writes to AsyncStorage. A player who plays on in-memory defaults can overwrite a save that is still on disk. P-01 only blocks the migration write (P-7). Any other write is untouched. This matches W0 ruling W0-8's "hardening" note, and I made no change.
6. **Emulator state left behind:** the P-01 build is installed with the seeded legacy save plus `arrows_schema_version=1`, adbd runs as root, and all three animation scales are 1. They were 0 before this task. Later capture tasks must set the scales explicitly anyway.
7. **Counts in the brief are stale:** it says 11 / 61; this branch's base was 12 / 111.
