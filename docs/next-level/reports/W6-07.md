# W6-07 report — record JavaScript fatals into int keys

- **Status:** DONE_WITH_CONCERNS
- **Base:** `6855aa3` on `next-level`
- **Primary concern:** the controlled Android release-path measurement was **0/10 persisted fatal
  records**, after positive and negative controls proved the detector.

## What changed

- `src/telemetry/crash.ts` (new)
  - Installs an injectable wrapper around React Native's previous global error handler.
  - For fatal errors only, best-effort writes pending count, FNV-1a `name:message` hash and screen
    enum inside `try/catch`, then always delegates once with the original arguments.
  - Drains one aggregate `error` event on a later cold start and resets pending to zero.
- `src/telemetry/__tests__/crash.test.ts` (new)
  - Eight tests cover handler chaining, a throwing store, the non-fatal path, exact hash and screen,
    raw-message privacy, aggregate drain/reset, zero-pending, and the real SaveSystem accessors.
- `src/core/saveSystem.ts`
  - Adds named accessors for P-01's already-registered fatal pending/hash/screen keys.
  - No key registry, persistence array, schema version, migration or reset behavior changed. There
    is no migration and no wipe risk.
- `App.tsx`
  - Tracks the current mapped telemetry screen next to every `screen_view` emission.
  - After successful hydration, seeds the existing remote telemetry kill state, installs the fatal
    handler once, and drains pending fatals. The existing early `PERF_MODE` return skips both.
- `docs/crash-reporting.md` (extended)
  - Preserves the existing W6-08 native-symbolication section and appends W6-07's data/privacy
    semantics, measured coverage and exclusions. The brief called this file new, but it already
    existed at the task base.

## Decisions

1. Stored fatal screen `0` (or any corrupt value sanitized to `0`) maps to `splash` while draining,
   because the telemetry schema deliberately allows only `splash | menu | game`. Valid screens use
   the binding `1/2/3` mapping.
2. One `emitScreenView` helper updates the module-level current screen immediately beside the
   W6-06 emission, including the amendment's future daily→game and gallery→menu mapping.
3. The existing remote telemetry kill state is seeded before draining so a persisted kill bit still
   suppresses telemetry. Pending is reset after the attempted emission, avoiding deferred shipment
   after a kill.
4. No synchronous-store redesign was added after fix round 1 validly measured 0/10 survival. The
   brief limits this task to measuring and documenting the result.
5. The brief called `docs/crash-reporting.md` new, but the base already contained W6-08's native
   crash-symbolication evidence. That content was preserved verbatim and the JS-fatal section was
   appended.

## Concerns

1. **The mechanism did not persist a fatal in any controlled emulator trial (0/10).** With the
   current microtask-scheduled AsyncStorage adapter, it provides no observed Android crash coverage.
2. Plain Jest invokes Watchman in this sandbox and fails before discovery; `--no-watchman` was
   required. The full suite itself is green.
3. The 10-trial probe was a JS-only release repack and debug-signed, rather than a second Gradle
   build. The task changes only TypeScript, and the repack used the same optimized Hermes steps over
   this task's freshly built Gradle release host.
