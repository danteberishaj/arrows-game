## Key findings (EXECUTED, `node scripts/art/icon-audit.mjs`, run twice, byte-identical stdout)

- `mark.png`: 512x512 RGBA. Furthest opaque radius (alpha>0) = 0.6897 of its own half-frame.
- Adaptive foreground: 1024x1024 RGBA, furthest opaque radius **0.5965** of the half-frame — reproduces
  the brief's cited 0.596 to well within its own ±0.005 tolerance. **0.596 < 0.611** (the cited safe
  zone): the foreground is inside the safe zone by 0.015 of the half-frame.
- Adaptive background: 1024x1024, 3 channels, no alpha (solid fill, as expected).
- `icon.png`: 1024x1024 RGBA, fully opaque (mark composited onto a full-bleed background before export).
- Play listing icon: 512x512, **3 channels, no alpha** — matches the brief's claim; this audit does not
  itself judge Play's current icon spec, per the brief.
- `mark.png`'s two dominant fully-opaque hues: `#6040e0` (61.6%, royal violet) and `#e04080` (14.8%,
  magenta/rose) — matches `Wordmark.tsx`'s own comment ("violet + magenta baked in"), independently of
  either palette's own `accent` token.
- `icon.png`'s edge-transition band (8 radial scanlines, upscale-softness baseline for W5-13): **1-3px**
  at the 1024px canvas (the mark is a ~1.84x raster upscale of the 512px source).
- Launcher capture (`emulator-5556`, API 31 AOSP launcher, plain `adb`, no reinstall, scales unchanged
  `1 1 1`): **the icon is not clipped by the launcher's circular mask** — I looked at
  `artifacts/W5-11/launcher-icon-crop.png` directly.
- Themed (monochrome) icon rendering: **UNVERIFIED (API 31)** — that AVD cannot show it (needs API 33+),
  per the brief's own acceptance criterion.
