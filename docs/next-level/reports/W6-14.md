## What changed

- `src/telemetry/sink.http.ts` (new)
  - Adds `createHttpSink({ url, fetchImpl, appState, consentGranted, killed, installId, cap })`.
  - Keeps a capped in-memory queue, dropping the oldest event first. `HTTP_SINK_CAP` is 500 and is
    marked `OWNER-PICKED STARTING VALUE`.
  - Projects every queued record onto the six existing envelope keys plus that event's exact
    `EventSchema` keys. Unknown/PII-shaped properties never reach JSON serialization.
  - A POST body is exactly `{ installId: "<hi>-<lo>", events: [...] }` with JSON content type.
  - The first request is started synchronously by `flush()`. One failed/rejected/non-2xx attempt is
    retried immediately; after two failures the batch remains queued for the next trigger.
  - Concurrent triggers share the current in-flight flush. Events appended during that request are
    kept for a later trigger rather than removed with the successful snapshot.
  - `session_end`, the first `app_open`, and AppState `background` trigger a flush. There is no timer.
  - Both `send()` and `flush()` re-check all four gates: compiled flag, non-empty URL, current
    consent predicate, and current telemetry kill bit.
  - `TELEMETRY_ENDPOINT_URL` is committed as the empty string.
- `src/telemetry/__tests__/sink.http.test.ts` (new)
  - 13 node tests cover the shipped closed inputs, all gates, batching, every trigger, synchronous
    AppState behavior without timer advancement, retry/retention, the 10,000-send cap, and
    schema-only serialization.
- `src/featureFlags.ts`
  - Adds `TELEMETRY_TRANSPORT = false`.
- `App.tsx`
  - Installs the HTTP sink after SaveSystem hydration and identity creation only when
    `TELEMETRY_TRANSPORT` is true.
  - Injects `fetch`, `AppState`, the W6-02 telemetry kill getter, the W6-05 install id, and
    `consentGranted: () => false` exactly as required by controller amendment F05.
  - Removes W6-06's development console sink. With the transport flag off, Telemetry therefore
    retains its default `noopSink`; the existing opt-in PERF memory sink is unchanged.
  - Disposes the transport's AppState subscription on App unmount.

No persistence key, `PersistenceKeys`, storage assertion, migration, or reset behavior changed.
The queue is memory-only: process death loses it by design, with no wipe or migration risk.

## Decisions

1. `createHttpSink` returns `{ send, flush, dispose }`, and App gives `send` to `Telemetry.useSink`.
   This keeps explicit test/control surfaces without changing W6-04's `TelemetrySink` type.
2. I read “the first flush after the next app_open” as: enqueue the first `app_open`, then start one
   automatic flush. Later synthetic app_open events do not retrigger that startup path. The test
   pins that interpretation.
3. Serialization is a whitelist projection rather than trusting the TypeScript type alone. That is
   defense in depth for the consent-sensitive boundary and makes the no-extra-property criterion
   true even if a future caller bypasses Telemetry validation.
4. A second trigger during an in-flight request shares that promise rather than duplicating the
   POST. The Android run confirms the real `session_end` plus background callbacks still produce
   one request.
5. The previous development console sink was removed because the binding brief says a false
   transport flag keeps `noopSink`. The explicit PERF memory sink remains because it is a benchmark
   probe, not a transport.
