## What I implemented

`scripts/analysis/shape-preview.ts`, a CLI with two modes:

- **`--name <Shape> --rows N [--out <dir>]`** — prints the shape's aspect, the `cols` derived from `rows` via the generator's own `clamp(roundHalfToEven(rows*aspect), 4, 46)` sizing math, the mask's cell count and fill fraction, an ASCII rendering of the mask, the shape's **capacity at the grid clamp** (always computed at rows=46, independent of the requested `--rows`, matching W3-01's `--capacity`), and the packed arrow count. Then writes `<out>/<Shape>-rows<N>.png`: the mask packed into arrows via `LevelGenerator.fillMask(mask, rows, cols, NormalConfig, new DotNetRandom(1234))` and drawn with `arrowArt`/`STROKE` from `src/ui/arrowGeometry.ts` — the same SVG-path construction `scripts/generate-promo-art.ts`'s `boardSvg` uses (read as reference only; that file has no exported members to import).
- **`--all [--out <dir>]`** — the same rasterize→pack→draw pipeline for every one of the 26 catalogue shapes (`ShapeLibrary.SimplePool ∪ MediumPool ∪ ComplexPool`, deduplicated — the same set `scripts/analysis/difficulty-probe.ts`'s local `allShapes()` builds) at rows 12, 24 and 46, printing a cell-count table to the console and writing one `<out>/contact-sheet.png`: 26 rows × 3 columns = 78 tiles, each labelled with the shape name, `rows×cols`, cell count and fill %.

Both modes import `ShapeDef.rasterize` and `LevelGenerator.fillMask` from `src/core` directly; the only "reimplemented" arithmetic is the same tiny `clamp`/`roundHalfToEven` row→col sizing helpers `difficulty-probe.ts` already ports locally (they're private to `levelGenerator.ts`, not part of rasterization) — a comment in the new file points at both origins so a reader doesn't mistake it for a third, independent implementation.

Default `--out` is `os.tmpdir()` per the brief; for this task's own verification I passed `--out artifacts/W3-04` (gitignored — confirmed via `git check-ignore -v`) so the PNGs exist as a reviewable artifact without being committed.

## Decisions

- **Difficulty config for packing:** used `Difficulties.config(Difficulty.Normal)` for every `fillMask` call in both modes. Arbitrary but fixed and consistent with W3-01's own `--capacity`, which also packs under Normal — difficulty only changes `maxLen`/bend odds, never the mask or its cell count, so this choice cannot affect the acceptance cross-checks.
- **Preview seed:** `DotNetRandom(1234)` for every tile in both modes (brief specifies 1234 for the single-shape PNG; I reused it for the contact sheet too for determinism and consistency rather than picking a second, unspecified seed).
- **Contact-sheet tile scale:** fixed 4 px/cell across all tiles (not a fixed tile box), so a shape's on-sheet size visibly grows with its row count — this is the simplest layout that satisfies "every shape at rows 12, 24 and 46" without inventing a normalization scheme the brief doesn't ask for.
- **Name matching:** case-insensitive match on `ShapeDef.name` for `--name`, with the full shape list in the error message if no match — a usability choice, not a behavior the brief specifies either way.
- **`--all`/`--name` are mutually exclusive**, following `difficulty-probe.ts`'s own "only one aggregate mode at a time" precedent.
