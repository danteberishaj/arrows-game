## Decisions

1. The rewarded fake starts ready so the continue control is pressable, then changes readiness to not-ready before `showRewarded` resolves `false`. Starting not-ready would disable the control and never exercise `onContinueWithAd`; the transition models the real readiness loss around a failed show while satisfying W0-02's unavailable-state contract.
2. The heart readout assertion counts the actual filled heart-path props emitted by `HeartPips`. It checks React component state/output only; it does not claim that native SVG pixels rendered correctly.
3. The test retries after the failed continue, restores readiness, and presses the real hint control in the same scenario. This keeps the suite to the brief's single component contract while proving both unearned reward paths.
4. `benchmarkMode` and `feedbackEnabled={false}` remove unrelated persistence, interstitial pacing, sound, and haptic side effects without bypassing the `GameScreen` callbacks under test.
5. The install retains W6-10's Node 20-compatible `@testing-library/react-native@^13.3.3` and `--legacy-peer-deps` resolution. Upgrading Node or dependencies is outside W6-11.
