# W4-06 — Daily board entry, route and done-state (`META_DAILY`, default OFF)

Implementer report, 2026-09-25. BASE = `d31d75b`. Requirements: `task-W4-06-brief.md` (with its
binding controller amendments), `codex/W4-06-addendum.md` (binding, newer) and `codex/GLOBAL.md`.
Raw evidence is under `artifacts/W4-06/` (gitignored). Nothing was committed; the controller owns git.

## Outcome

With `EXPO_PUBLIC_META_DAILY=1`, the menu shows one quiet text control under the Play pill once
the player has solved at least one board. It reads `Today's board`; after a clear it reads
`Today's board · done` and cannot be pressed. It opens the day's shared board
(`generateDaily(SaveSystem.today())`, with the day fixed when the player enters). The header reads
`TODAY`. A clear counts as a solve (totals, perfect streak, day streak) and writes
`arrows_daily_last_day = day`. It never moves `currentLevel` and never counts toward the
interstitial, on a clear or on a loss. The win panel reads `Today · <shape> · <n> arrows` and shows
`Done`, which goes straight back to the menu: no interstitial, no next board, no level scrim. Retry
rebuilds the same day's board and goes through the campaign's Retry routing (the scrim when
`META_LEVEL_TRANSITION` is on and reduced motion is off). With the flag OFF, the menu and every flow
are identical to BASE (see "Flag OFF").

## Decisions

1. **Daily sessions use `index = day`** (the aggregator's `levelIndex`, ruling F09) and carry
   `day`. Every campaign use of `levelIndex` (pointer, Next, header, subline) branches on
   `dailyDay` first.
2. **App stores the day when the player enters** (`setDailyDay(SaveSystem.today())` in `onDaily`)
   instead of computing `daily={{ day: SaveSystem.today() }}` during render, so a re-render after
   midnight cannot change the board's day. The day is the local calendar day, the same unit as the
   streak (W4-03's `generateDaily` contract), so the daily flips at local midnight.
3. **Copy location.** The menu labels live in `dailyEntryState.ts`, so the brief's grep covers
   them. The game copy lives in `GameScreen` constants. All of it is marked OWNER-PICKED.
4. **Placement at 360×640.**
   - A 44 dp box centred in the column cannot fit between the pill (bottom at 458.7 dp) and the
     stats line (top at 479.7 dp). Measured: 21 dp of room, and adding h dp to a centred column puts
     the entry's bottom at 458.7 + h/2.
   - So while the entry is visible, `upper.marginBottom` is 56 → 36. The entry box is 44 dp with a
     4 dp top margin. OWNER-PICKED; W4-10 owns the final layout.
   - With the flag OFF or the entry hidden, the exact BASE style object is used, so the trees stay
     identical.
5. **The done state is plain text** in the same box, with no role and no handler. No replay (ruling
   W4-7).
6. **Duplicate taps on `Done`** within one frame call `onHome` once.
7. **Assist stage.** A perfect daily clear during FTUE assist sets the stage to DONE, exactly as a
   perfect campaign clear does. The daily is "a solve like any other"; not special-cased.
8. **Capture builds.**
   - All builds are JS repacks (`artifacts/W4-06/scripts/repack.sh`) over the installed 87ec519
     release APK. Native code is identical: `87ec519..d31d75b` changes only App.tsx and telemetry
     JS. No gradle build ran.
   - The scripted captures use the fit camera (`META_ZOOMED_CAMERA` unset), following the W2-04 and
     W2-05 precedent, so computed taps land. The handback build carries the full 2026-09-24 flag set
     plus `META_DAILY=1`.
   - The BASE repack comes from the working tree with the 10 modified files temporarily replaced by
     their `d31d75b` content (`git diff` empty during the build), then restored. The restore was
     verified by diff sha.
   - A first BASE attempt from a `git archive` copy with a symlinked `node_modules` shipped font
     assets that did not resolve: Fredoka fell back to the system font, which the screenshot caught.
     It was discarded.
   - **Provenance.** The capture builds (`w406-on-fit`, `w406-off-fit`) were built from working-tree
     diff sha `a207ce9cfdab`. After the captures I reworded two comments so the copy grep is clean:
     `dailyEntryState.ts` line 5 and `HomeScreen.tsx` line 77. The final tree is `b09426c54910`, and
     the gates above were run on it. The handback APK was rebuilt from the final tree. The HBC bundle
     embeds a source hash, so the two bundles cannot be compared byte for byte.
9. **Seeding.** Seeding used the real flow at native geometry: fresh install, T1, T2, then Level 1
   cleared by 60 checked taps (`seed/solve.log`). No storage was seeded directly.

## Concerns

- **`session_end.lastLevelIndex` carries the day number after a daily.** Observed on web:
  `lastLevelIndex: 2459`. `session_end` has no `mode` field. The W6 decision rules (already a
  deferred note for rows 2 and 3) must filter `level_end.mode` and treat `lastLevelIndex` with care.
- **Installed APK is debug-signed** (repack), not upload-key signed.
  - An `adb install -r` of a gradle upload-key build will fail with `INSTALL_FAILED_UPDATE_INCOMPATIBLE`
    until `adb -s emulator-5556 uninstall com.danteb.arrows`, which wipes the seeded state.
  - At task start I uninstalled the upload-signed 87ec519 app, which wiped its test data (Level 1,
    unsolved).
- **Tight layout margin.** The margin between the entry box and the stats line at 360×640 with the
  banner is 7 dp at font scale 1.0. Larger accessibility font scales were not measured
  (UNVERIFIED). The BASE pill-to-stats gap has the same exposure.
- **Flag-OFF bundles still contain the daily strings** as dead-at-runtime code (a runtime `useState`
  gate, not a compile-time fold). Not player-visible.
- **Day rollover was not exercised on a device.** `adb root` is forbidden, so the clock was not
  moved. The injected-clock tests cover it: a clear after midnight records the board's day.
- **UNVERIFIED-DEVICE:** tap comfort and layout on a physical small phone; iOS (no iOS build).
- **Browser storage.** The dev browser's localStorage now holds today's daily as done, with 3 solves.
- **Ad clicks.** No tap touched an ad. `logcat` holds 0 `aclk` lines for the session. The only
  positive control for this detector is from an earlier session (ADMOB-B).
