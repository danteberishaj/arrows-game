The floor is an absolute distance: 4 pt over the live cell size in points (`cellPt` = board units per cell × the camera
scale, read each frame on the UI thread, so a pinch during a bump is followed). It is never a multiplier on the 0.5
amplitude. Same timing (300 ms), same shape (rest at both ends, peak at k = 0.3195). It is active only when
`cellPt < 4 / 0.22260 = 17.97 pt`; every larger view gets the shipped value exactly.

**RULINGs**
1. **Flag name.** The spec names `blockedAnticipation` in `src/ui/motionFlags.ts`; that file does not exist (W2's motion
   flags live in `src/featureFlags.ts`, its header says so). The rulings doc names
   `EXPO_PUBLIC_META_BLOCKED_ANTICIPATION`. Used: `META_BLOCKED_ANTICIPATION` in `featureFlags.ts`. The name says
   "anticipation" although the owner ruled no pull-back; kept for traceability to the spec and the rulings doc.
2. **No anticipation.** Spec Change 2-3 and acceptance items about the negative excursion do not apply (owner: no
   pull-back). `d >= 0` stays asserted for every zoom.
3. **Kotlin skin renderer not covered.** With `META_SKIN_PICKER` on and a style selected, the bump is drawn by
   `SkinMotion.kt` with its own copy of the shipped curve. The spec's file list has only the two JS renderers, the picker
   is default OFF, and changing the native module needs its own capture. Follow-up if skins ship: pass the floor through
   `skinConfig` (as W2-09's ink hold is).
4. **The spec's "endpoints exactly 0":** `blockedBumpAt(1)` is 0.5·sin(π)·e⁻² ≈ 8e-18 in floating point (as it always
   was); the tests assert k = 0 is exactly 0 and k = 1 is 0 to 12 decimals.

- **Target ≥ 4 pt: met.** Run 2's median of the well-sampled trials is 4.01 pt; the whole range is 3.74-4.07 pt.
- **Resolution:** one recording pixel is 2 device px = 0.57 pt; the sub-pixel template shift agreed with the prediction
  to within 1 device px (0.29 pt) in W2-10 and here (OFF 7.68 vs 7.73 predicted; ON 14.02 vs 14.00). So the result is
  4.0 pt ± 0.3 pt. The 3.74 pt low end (13.10 px, 8 frames) is inside that band plus sampling.
- **Sampling reconciliation:** the recorder ran at 7-39 Hz under host load. Every trial's frame count in its 300 ms
  window matches 0.3 s × its measured rate (e.g. 10 vs 10.3, 13 vs 11.6, 4 vs 3.9). A trial with 1-3 frames in the
  window can miss the 96 ms peak and read low (run 1: 9.97, 11.14, 12.62; run 2: 6.46, 10.40). Those are listed above as
  valid but not used for the median: undersampling only lowers a reading, never raises it.
- **Unchanged views:** max zoom (D, 64 pt cells) measured 14.1 pt against the shipped 14.25 pt prediction (floor
  inactive). Level 1 at fit (A, 19.34 pt cells, shipped 4.31 pt) and max zoom (B) are above 17.97 pt per cell, so they
