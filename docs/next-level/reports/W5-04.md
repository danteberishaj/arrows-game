## Capture method

- **Driver.** `artifacts/W5-04/scripts/winshot.mjs`. P-02's `capture.mjs --step won` is pinned to
  level 3827 (`benchmark.mjs createSingleLevelPlan`), so this driver reuses P-02's own pieces for
  any level:
  - `applyMotionScale`: sets all three scales, force-stops, relaunches, and reads back the scales
    and the app's `useReducedMotion`.
  - `dumpUiXml`, `screencapPng`, `readWm`.
  - `cellCenterForBoard` with `FIT_MARGIN`, over the live board bounds.
- **Plan.** `scripts/plan.ts` solves in `findHint()` order, tapping head cells (soak-plan's rule).
- **Taps.** `input tap` in batches of 10. After every batch, `N left` must drop by exactly 10, or
  the run aborts. **Zero divergences in 15 solves.**
- **Phase proof.** The WON phase is proven by a saved uiautomator dump before the screenshot:
  `perf-next-level` + `Cleared!` in PERF builds, `Cleared!` + `Done|Next level` otherwise. A
  release build has no phase log line: `[measure-clear]` is `__DEV__`-only (App.tsx:57-64).
- **Settling.** Screenshots are taken 2.5 s after the proof dump, and that dump itself only
  succeeds once the screen idles (after the star stagger).
- **Manifests.** Each capture directory has `manifest.json` (argv, git, device, installed APK sha,
  wm read-back, motion read-back plus app value, plan, board bounds, badge node, panel texts),
  `board-ready.png/.xml`, `phase-proof.xml`, `panel.xml` and the PNG.
- **Analysis.** `scripts/analyze.py` classifies each pixel of the badge box (from the
  `win-silhouette` resource-id bounds) as nearest `accent` or `surface`. It compares the result
  with the mask rasterised the way `silhouettePath` centres it, and reads the badge-centre pixel.
  Summary: `artifacts/W5-04/compare/summary.txt`.

## Decisions

1. **One file outside the brief:** `contrastAudit.ts`. Its site checks pin `GameScreen.tsx` line
   numbers, so any insertion above them fails 21 tests. Every earlier GameScreen commit updated it
   (W2-04, W2-05, W4-06, W4-07). I also added the `win-silhouette` usage row so the new `accent`
   graphic is audited.
2. **The flag-OFF proof is a snapshot written at BASE**, plus an "ON minus badge == OFF" identity
   test. The snapshot is scoped to the panel node, not the whole screen, so that header work
   (W5-02/W5-06) does not churn it.
3. **`testID="win-silhouette"` is always set**, not only in benchmark mode. It changes nothing
   with the flag OFF (no element). It gives uiautomator the badge bounds on any build.
4. **The memo is gated by the flag**, so OFF never computes a path. ON computes on every level
   load, as the brief specifies. Cost, INFERRED from node (not Hermes): median 0.046 ms, max
   0.205 ms over levels 0–199 (`gates/path-cost-node.txt`).
5. **The badge is decorative for screen readers.** The Svg is not focusable, and the subline
   still names the shape (brief: "no new text").
6. **PERF builds were used for the level-specific captures.** P-02's standard is the only way to
   open level 167/38/53 without playing through. The panel differs from a player's only by the
   hidden `perf-*` testIDs and the absent streak line. The real player tree was captured
   separately (row 7).
7. **Owner screenshots come from the fit camera.** The handback build has the zoomed camera; the
   badge does not depend on the camera.

## Concerns

1. `git diff --stat` includes `src/ui/contrastAudit.ts` (Decision 1). The brief's two-file list
   cannot hold for any `GameScreen.tsx` insertion while the audit pins line numbers.
2. **The daily capture used a capture-only patch.** Today's daily (day 2459) was already done on
   the emulator save (W4-06), so the entry is `done`. Changing the emulator date would have mutated
   the streak and freeze state. Instead, a PERF build was made with a temporary two-line App.tsx
   patch that boots into `daily` for `SaveSystem.today()`
   (`scripts/capture-only-daily-boot.patch`). It was never committed and restored immediately:
   tracked-diff sha `6859a6e2aead` before and after. The GameScreen daily path it exercises is the
   real one.
3. **The emulator save moved on.** The real-tree 360×640 capture cleared campaign Level 2 on the
   owner's emulator save: Level 2 → **Level 3**, 4 → **5 solves**, best perfect run **5**,
   `finishedGames` +1. The next "Next level" press may therefore show the paced TEST interstitial.
   No ad was tapped at any point.
4. **Taste calls for W5-20:**
   - The gap from badge to stars looks larger than from title to badge. The stars row is
     `minHeight: 52`, bottom-aligned, and `silhouettePath` centres the whole mask grid, so a shape
     with empty margin (Cat) floats high in its 64 dp box.
   - The silhouettes are visibly stair-stepped (cell boundaries) at 64 dp.
   - Both belong to the owner's size pick (48/64/96) and to W5-05 (panel hierarchy).
