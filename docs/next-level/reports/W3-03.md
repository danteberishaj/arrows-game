## What I implemented

Per the brief: changed `ShapeDef`'s constructor from `(name, simple, aspect, fillsGrid, inside)` to `(name, aspect, inside)`, removed the `simple` and `fillsGrid` fields (and their doc comments) from the class, and updated all 26 `new ShapeDef(...)` call sites in `ShapeLibrary` to the 3-arg form. Confirmed no other file in `src`/`scripts`/`modules`/`App.tsx` constructs `ShapeDef` directly (`grep -rn "new ShapeDef(" src scripts modules App.tsx` → only the 26 hits inside `shapeLibrary.ts` itself, both before and after).

## Brief premise was stale (found during work, not a routine judgment call)

The brief's PRE-FIX REPRODUCTION claims "`grep -rn "fillsGrid\|\.simple\b" src scripts modules App.tsx` hits only the class itself (EXECUTED 2026-09-16)." That was true on 2026-09-16, but **`scripts/analysis/gallery-contact-sheet.ts`, committed 2026-09-25 as `f8125de` (`feat(W4-08)`, nine days after the brief's grep), genuinely reads `shape.fillsGrid`** three times: as a column header string, as a per-shape boolean it prints, and to count grid-filling vs. silhouette shapes in a console summary. This is a real consumer, not a stale reference — it landed on `next-level` after the brief's evidence was captured and before this task ran.

Deleting the field as specified would have broken that script (`npx tsc --noEmit` would fail on `scripts/analysis/gallery-contact-sheet.ts`), and it's not in W3-03's "Files:" list. I judged the fix to be in scope of "delete the dead field cleanly" rather than a reason to stop: `fillsGrid` was only ever `true` for `Square`/`Rectangle` (both `() => true` insides) in the current 26-shape catalogue, so I reproduced the same boolean in the script from the shape's name instead of the field, with a comment explaining why and pointing at W3-03. I renamed the local helper/column from `fillsGrid`/`gridFilling`-adjacent names to avoid leaving a same-named ghost that a future `grep fillsGrid` would misread as "the field still exists somewhere" — it's `isGridFilling` / `gridFilling` now, a script-local concept, not a `ShapeDef` API.

I also had to touch `src/core/dailyBoard.ts`: its existing doc comment already said "deliberately NOT derived from `ShapeDef.fillsGrid`, which W3-03 deletes" (this task was anticipated there) — but the literal string `ShapeDef.fillsGrid` in that comment itself fails the brief's own zero-hits grep, so I reworded it to describe the field without naming it verbatim, keeping the historical note.

**Net effect:** the field is fully gone from `ShapeDef` (the brief's real goal), the one genuine external reader keeps identical output (verified by running it, see below), and the literal grep in the brief's acceptance criteria now passes for real, not just against a premise that had already gone stale.

## Decisions

- Renamed the script-local grid-filling check to `isGridFilling` (not `fillsGrid`) so a future `grep fillsGrid` reliably means "the deleted `ShapeDef` field," not "also this script." - Did not add a shared "is this shape a full-grid fill" helper in `shapeCatalogue.ts` or similar — the brief's non-goals rule out any pool/API change, and the diagnostic script is the only consumer; a two-name `Set` local to that file is the smallest fix.
