# W1-06 — Condition-defined early-board assist

## Status

`DONE_WITH_CONCERNS`

The condition-defined assist is implemented behind the existing default-OFF `FTUE_ASSIST_ENABLED` flag. With both FTUE flags enabled at stage 2, distinct blocked taps are free until the board's first successful removal; blocked taps after a removal use the normal ledger. The assist ends on the player's first perfect real-board clear, independent of whether the assist flag was enabled for that clear.

## Implementation details

- `blockedTapCost` returns `{ chargeHeart: false, consumeGrace: false }` only when mode is `assist` and the current board has no successful removal. Once `removalsThisBoard > 0`, it delegates to `ledgerCharge`, including repeat-tap protection.
- `removalsThisBoardRef` increments in `onRemoved` and resets through `loadSession`, which is used for Next, Retry, tutorial re-deals, and the post-T2 hand-off. Rewarded continue does not call `loadSession`, so the count is retained.
- Tutorial mode has precedence over assist mode. Assist mode additionally requires both flags and `SaveSystem.ftueStage === 2`; stage 3 and normal sessions use normal mode.
- At the top of the real-board clear branch, before any stage write, `GameScreen` reads `SaveSystem.ftueStage` once and stores whether it was stage 2 in `assistedAtClearRef`. The ref survives the delayed win transition and is the binding F12 hand-off for W4-11.
- A real-board clear at stage 2 advances to stage 3 only when `heartsRef.current === level.hearts`. This write is independent of `FTUE_ASSIST_ENABLED`; non-perfect clears remain at stage 2.

## Decisions and tradeoffs

- Reused the existing `DONE_STAGE` constant instead of writing another bare `3`; exporting it keeps the route predicate and stage transition aligned.
- Kept `assistedAtClearRef` even though W4-11 is not present yet. It is intentionally captured before the stage write and available to the future delayed won-phase policy call, as required by controller amendment F12.
- Used JS-only APK repacks because the brief requires behavior capture, not a native Gradle change, and the global instructions explicitly permit this route.
- Retained invalid diagnostic capture attempts for auditability while naming and excluding them from acceptance evidence.

## Concerns and unverified items

- **UNVERIFIED-DEVICE:** Physical-phone behavior was not verified. Emulator native and Expo web evidence passed.
- **INFERRED:** A player who never clears perfectly can retain the assist indefinitely, although it applies only before each board's first successful removal; after that removal, normal heart cost resumes.
- **UNVERIFIED-DEVICE:** Whether this forgiveness over-corrects into a too-easy hazard is unmeasured. Nothing in W1-06 measures learning.
- **INFERRED:** Stacking this assist with W3's level-1 rebuild may overshoot difficulty. `FTUE_ASSIST_ENABLED` must remain OFF until the W3-12 joint W1+W3 sweep and W3-17 playtest have reported.
- **INFERRED:** Rollback is `FTUE_ASSIST_ENABLED` OFF; it defaults OFF.
