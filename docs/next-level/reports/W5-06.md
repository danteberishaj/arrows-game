## Decisions

1. **The badge is an `Svg` sibling in a row, not an inline image inside one `Text`:** RN `Text` cannot size an inline
   `Svg` to its own line height; the row keeps the tier Text's baseline for the parent row (it is the first child).
2. **Height from `onLayout` of the tier Text, read once, cached per font scale** (the brief: "read once from onLayout …
   not a constant"). The per-font-scale cache means only the first game screen at a font scale has to wait for a
   layout; the recording shows no badge-less frame even then.
3. **A variant that re-read the line on every ≥ 1 px layout change was built, captured and reverted.** It was a guess at
   why the badge is 67 px while uiautomator reports the row's Text as 69 px at font scale 1.3. It changed nothing: both
   builds draw a 67 px badge, i.e. `onLayout` reports 19.143 dp there while the native Text view's bounds are 19.714 dp
   (Concern 2). Reverted to the brief's "read once".
4. **BASE comparisons use `w207-off`** (HEAD + W5-03 + W2-07, flag off).

## Concerns

1. **Recognisability is the owner's call** (the kill criterion). At 15 dp (53 device px) a 37x37 Cat reads as a cat
   head on the emulator; Ring reads as a ring; Butterfly (32x35) and the thin Bolt are blobs / slivers. The W5-01 sheet
   at this size shows all 26 shapes.
2. **At font scale 1.3 the badge is 2 px shorter than the row's Text bounds** (67 vs 69 px): `onLayout` reports the
   Text 0.57 dp shorter than the native view's bounds at a fractional font size. The header height is unchanged
   (`[board-viewport]` 790.2857 in both arms), so this only shows as the badge being very slightly short at 1.3.
3. **UNVERIFIED-DEVICE:** recognisability on a physical panel (the brief's own item); iOS text layout.
