# W5 — Art direction

Arrows is a calm visual-search game. What decides whether a session works is legibility, and the thing most worth showing is the silhouette the arrows fill. W5 makes the screen look drawn on purpose and stop looking like a prototype. The controls become real icons instead of OS-font characters (Android paints the hint button as a yellow emoji). The `{remaining} left` counter stops shifting sideways on every tap. The win and lose panels get an edge you can see. And for the first time the player is shown the picture they just cleared as a picture, not as a 12 pt word. W5 adds no rule and no persisted key. It adds no runtime dependency, and it draws nothing on the board while arrows are on it. Every player-visible change ships behind a build-time flag in `src/ui/artConfig.ts` that defaults to OFF. The owner accepts it from the W5-19 packet in W5-20. The counter reflow fix, the ad-label font fix and the doc corrections are defect fixes and have no flag.

**Merged from:** W5-draft1 steps W5-01 … W5-15 (plus escalations E-wordmark, E-bottombar, E-hairline, E-texture, E-ipad, E-trail) and W5-draft2 steps W5-01 … W5-14 (plus its four escalations). Red-team findings applied (ids below are draft 2's): brand-13 on W5-07 (the dead bands are a brand inversion: an owner screenshot decision, relocation only, no duplicated badge), W5-01 (one capture harness, not three), W5-11 (the fillet is sub-perceptual: collapse it to a doc fix), W0-07/W5-02 (one contrast owner), the missing chrome and word census, and the 20 dp and 64 dp badge sizes, which were picked; performance-16 on W5-06 (the clear reveal spends W2's post-clear window and must wait for one timeline decision and the reduce-motion policy), W5-12 (a recording at `animator_duration_scale 0` shows a stationary dash, so the scale and `useReducedMotion` must be logged; the resting width comes before any escalation) and W2-09/W2-05/W5-06 (one timeline owner); evidence-15 on W5-07 (a zero-margin gate against a modelled viewport; the 96 dp, +15 dp and 1.02× values were invented), W5-05 (the 3×-run-count bound and the badge sizes were invented), W2-11 vs W5-13 (contradictory theme-transition mechanisms), W2-10 vs W5-08 (the heart-refill pop was specified twice) and W5-06 (its vague perf criterion); skeptical-14 on W5-04 (blocked on the wordmark decision; split in-app from launcher), W5-07 (must consume W1-01's logged viewport) and the missing web-regression coverage.

## W5-01 — Add a pure mask-to-outline function for silhouettes, and a sheet renderer to size them

- **Status:** READY
- **Effort:** M
- **Depends on:** none
- **Flag:** none (no player-visible caller until W5-04 / W5-06, which are flagged)
- **Files:** `src/ui/silhouette.ts` (new), `src/ui/__tests__/silhouette.test.ts` (new), `scripts/art/silhouette-sheet.ts` (new; `scripts/art/` does not exist), `.gitignore` (add `out/art/`)

### Context
Every level packs a silhouette. `GeneratedLevel.mask` (`src/core/levelGenerator.ts:16`, filled at `:68-71`, returned at `:85`) reaches `GameScreen` as `session.level` (`src/ui/gameSessionLifecycle.ts:17-22`). No code under `src/ui` reads it: `grep -rn mask src/ui` returns 0 hits. The player sees the shape only as a word: in the 12 pt `MissionLabel` (`GameScreen.tsx:336`) and in the win-panel subline (`:270`). Under Track A, silhouette novelty is part of the core loop, so this is the most ownable content the game has.

There are two consumers here: the win-panel badge (W5-04) and the header badge (W5-06). W4's shape gallery needs the same drawing. W5 owns this function and W4 consumes it (W4-08 and W4-09 depend on this task). Note that W1's tutorial boards set `mask: []` and `shapeName: ''`.

The drafts proposed two algorithms. Row-run rects abut vertically and can show antialiasing seams. A nonzero-winding contour silently fills the Ring's hole if a loop is traced in the wrong direction. This task uses cell-boundary tracing with the even-odd fill rule (react-native-svg's `fillRule="evenodd"` exists: `node_modules/react-native-svg/src/lib/extract/types.ts:19`), so loop orientation cannot matter.

### Change
- `silhouettePath(mask: readonly (readonly boolean[])[], size: number): string`
  - Returns an SVG path `d` inside a `size`×`size` box, with cell = `size / max(rows, cols)` and the shape centred, keeping its aspect ratio.
  - A boundary edge exists wherever a `true` cell borders a `false` cell or the grid edge. Chain the edges into closed loops and merge collinear runs. Emit each loop as `M … Z`.
  - Consumers must render with `fillRule="evenodd"`.
  - An empty mask, or one with no `true` cell, returns `''`.
- `scripts/art/silhouette-sheet.ts` (run with `npx tsx`):
  - For each of the 26 shapes (the deduplicated union of the three pools), rasterize at the rows and cols of its first-appearance level (scan `LevelGenerator.generate` from 0; don't hardcode indices).
  - Render the path at every size in `--sizes` (required argument; no default) at 3.5 px/dp, which is the AVD's 560 dpi. Draw each in `accent` on `surface` and `inkDim` on `bg`, in both palettes imported from `src/ui/theme.ts`.
  - Write one contact sheet per size to `out/art/silhouette-sheet-<size>dp.png`.

### Non-goals
Rendering anything in the app (W5-04, W5-06, W5-17). Changing the generator or `ShapeLibrary`. The gallery layout (W4).

### Acceptance criteria
- `npx jest silhouette` passes the following cases:
  - (a) For all 26 `ShapeDef`s rasterized at 20×20, 37×37 and 46×31, an even-odd point-in-polygon test at every cell centre reproduces the mask exactly. The test asserts that 26 distinct names were covered.
  - (b) A hand-written 5×5 ring gives exactly 2 `M` commands, and its centre cell tests outside.
  - (c) A full 3×3 mask gives one loop with exactly 4 vertices.
  - (d) Two cells touching only at a corner produce closed loops and still pass (a)'s round-trip.
  - (e) `[]` and an all-false mask return `''`.
  - (f) No output contains `NaN`, and every coordinate lies in `[0, size]`.
- `npx tsx scripts/art/silhouette-sheet.ts --sizes 16,24,48,64,96` writes 5 PNGs. Each tile is `size × 3.5` px square. The run prints the shape-to-level-index table it used.
- `npx tsc --noEmit` is clean.

### Verification
1. PRE-FIX REPRODUCTION: `ls src/ui/silhouette.ts` fails, and `grep -rn mask src/ui` returns 0 hits. There is no silhouette rendering to reproduce, only its absence.
2. `npx jest silhouette`. The round-trip over all 26 real shapes is exactly the failure a tracer can have (dropped or doubled cells, filled holes), and it uses the shipped `ShapeDef.inside` functions, not hand-copied data. The sheet run proves the path renders through a real SVG rasterizer.
3. TDD: write test (a) first. It fails because the module does not exist.
4. UNVERIFIED-DEVICE: whether a given size is recognisable on a phone panel. The sheet is input to the owner's size choice, not proof.

### Risk and rollback
Risk: the loop linker mis-chains at a vertex shared by two diagonal cells. Case (d) covers that. Risk: a later W3 catalogue change adds shapes. Test (a) derives its shape list from the pools and doesn't need an update. Rollback: delete the new files. Nothing calls them.

It defines the width through normal layout, so the system font scale and the web text engine are handled for free.
   - Over the ghost, the real `{remaining}` `Text`, absolutely filling the slot with `textAlign: 'right'`.
   - `WIDEST_DIGIT = '2'`, with a comment that cites the script below.
2. Add `scripts/analysis/font-digits.mjs`. It parses both Fredoka TTFs and prints the GSUB and GPOS feature tags and the hmtx advances for U+0030…U+0039.

### Non-goals
A type scale (W5-08). `LEVEL N`, which changes per level, not per tap. The menu. Any change to `MissionLabel`.

### Acceptance criteria
- `node scripts/analysis/font-digits.mjs` prints exactly the feature lists and digit advances listed in the measured facts for both weights.
- `grep -rnE "fontVariant|tabular" src App.tsx` returns 0 hits.

- At `adb shell settings put system font_scale 1.3` (restored to `1.0` afterwards), a 3-digit count on index 137 is not clipped. At the 360×780 dp geometry (W1-01's `wm` override), on Butterfly (index 119), the header row does not wrap.
