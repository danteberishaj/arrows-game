# W2 — The reward loop (motion and feel)

The moments a player keeps hitting (a blocked tap explaining itself, the last heart going, a level
ending and the next one arriving, a heart coming back after a rewarded ad, the theme flipping at
night) should each have a beginning, a middle and an end instead of a hard cut. They must also stay
honest under OS Reduce Motion: feedback that carries information gets a static version, and
decorative motion is skipped. Under Track A this workstream is supporting work, not the core loop.
Two tasks are accessibility and teaching defects and belong next to W0: **W2-01** (reduce-motion
census) and **W2-03** (the lose panel cuts off the blocker flash). **W2-02** is a documentation fix.
Everything else is player-visible feel work. It ships behind flags that default OFF, and it must not
take effort away from W3's legibility and difficulty work. Every capture in this file comes from the
P-02 instrument, run at motion scale 1 unless a task says otherwise. Frame-count thresholds are
checked against the recorder frame rate that P-02 measures and records in its manifest, never
against an assumed 60 fps.

### Context
`ReduceMotion` is not imported anywhere in `src/` or `modules/`, so every Reanimated animation inherits `ReduceMotion.System`. Reanimated 4.5.1 handles that setting as follows (READ from `node_modules/react-native-reanimated/src`):
- `animation/util.ts:503-512`: when reduce motion is on, an animation sets `current = toValue`, gets `onFrame = () => true`, and finishes on its first frame. Its completion callback still fires.
- `animation/delay.ts:50`: `withDelay` skips its delay entirely.
- `animation/decay/decay.ts:107-113` plus `util.ts`: `withDecay` clamps its start value and ends at once, so a pan fling stops dead.
- `ReducedMotion.ts:16`: the system value is read **once, at JS module init**. After changing the OS setting the app must be force-stopped and relaunched.
- `android/.../NativeProxy.kt:329`: on Android the signal is `Settings.Global.TRANSITION_ANIMATION_SCALE == 0`. It is not `animator_duration_scale`. `scripts/perf/android/benchmark.mjs:351-353` sets both to 0, so every harness run so far measured the reduced-motion variant.
- `ReducedMotion.ts:8-11`: on web the signal is `matchMedia('(prefers-reduced-motion: reduce)')`.

W0-04 owns the six information-carrying `withTiming` sites: `BoardView.tsx:842, 887, 934` and `StaticBoardSurface.native.tsx:264, 308, 348`. Under reduce motion they must render a static equivalent. **Do not touch them here.** These call sites remain at `da93dcd`:

| Site | Call | What happens today under OS reduce motion (INFERRED from reading, not yet captured) |
|---|---|---|
| `SplashScreen.tsx:44-47` | `withDelay` + `withSpring`/`withTiming` | The delays are skipped, `out` finishes on the first frame, and `onDone` fires at once. The splash is effectively skipped. |
| `SplashScreen.tsx:53` | skip `withTiming` | Instant |
| `BoardView.tsx:310-311` | hint recentre `withTiming` 280 ms | The viewport snaps to the hint |

| `BoardView.tsx:980` | web `ExitTrail` `withTiming` | k jumps to 1, so `opacity: reducedMotion ? 1 - kk` (:995) is 0 on the first frame. **On web the exiting arrow just vanishes**, while native draws a stationary fading dash. The two renderers disagree. |
| `GameScreen.tsx:385` | heart-loss `withSpring` | No pop. The fill colour change (:395) still carries the information. |
| `GameScreen.tsx:450` | star `withDelay(withSpring)` | All stars appear at once, while the star chirps still fire on their own `setTimeout` delays (:453) |
| `HomeScreen.tsx:50-51` | Play pill `withRepeat(withTiming)` | Unknown resting scale. Capture it. |
| `App.tsx:63, :75` | `entering={FadeIn.duration(180)}` | Instant |

**Native exit protocol.** Reanimated does not control this path. `BoardView.tsx:394` passes `useReducedMotion()` into the payload, and `nativeExitAnimation.ts:30` serialises it as the fourth header field. `ArrowsBoardView.kt:163` parses it. `:269` sets `travelled = 0`, `:271` switches to a linear `1f - progress` fade, and `:288` translates the head by `travelled` (so by 0). Swift mirrors this at `ArrowsBoardView.swift:168, :177-183, :191-193`. Under OS reduce motion the shipped exit is therefore a **stationary dash that fades linearly in place, and the arrowhead never moves**. No document records this and nobody has signed it off.
