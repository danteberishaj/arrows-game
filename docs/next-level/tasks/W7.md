# W7 — Monetisation, compliance, listing

After W7, a player in the EEA or UK is asked for ad consent by a Google-certified consent tool
before the ad SDK starts. Their choice reaches LevelPlay through its privacy APIs before `init`. A
refusal leaves the game fully playable, and no hint or continue is ever granted without an ad. Any
player can open the privacy policy, change their ad privacy choice and contact support from a
Settings sheet on the menu, and never from the board. The privacy policy, the Play Data safety
answers and the age posture all describe what the built artifact actually does, and they are
derived from that artifact rather than from memory. The Play listing gets its first real
screenshots and copy that sells a calm visual-search game, not a logic puzzle. W7 adds no IAP, no
new ad placement and no pacing rules. Pacing persistence is W0-05. Anything that needs a lawyer, a
console, a vendor account, the owner's LevelPlay data or an iOS build is marked BLOCKED, and the
agent-doable preparation for it is its own READY task.

## W7-01 — Add a consent state module and send LevelPlay's privacy calls before init

- **Status:** READY
- **Effort:** M
- **Depends on:** P-01 (`arrows_consent`; creates `src/core/__tests__/saveSystem.test.ts`), W0-01,
  W0-02 (creates `src/ui/adInit.ts`, the retryable init controller), W0-05. All four edit
  `src/ui/ads.tsx` before this task does.
- **Flag:** `CONSENT_GATE`, default `false`. With it OFF, the init path is byte-for-byte what W0-02
  left.
- **Files:** `src/ui/consent.ts` (new), `src/ui/__tests__/consent.test.ts` (new), `src/ui/ads.tsx`,
  `src/ui/adInit.ts` (from W0-02), `src/ui/__tests__/adInit.test.ts` (from W0-02), `App.tsx`,
  `src/core/saveSystem.ts` (accessor only), `src/core/__tests__/saveSystem.test.ts` (from P-01),
  `src/featureFlags.ts`

### Context
`initAds()` (`src/ui/ads.tsx:154-237`) calls `LevelPlay.init` (`:174`) with no privacy call before
it. Nothing anywhere in `src/` or `App.tsx` calls `LevelPlay.setConsent`,
`LevelPlayPrivacySettings.setCCPA`, `setCOPPA` or `setGDPRConsents` (grep: 0 hits). `app.json`
declares `com.google.android.gms.permission.AD_ID`. `plugins/withLevelPlay.js:17-21` injects
`play-services-appset`, `play-services-ads-identifier` and `play-services-basement`. So the shipped
binary initialises an ad SDK that reads advertising identifiers, and no lawful basis is captured
anywhere. Unity's LevelPlay React Native regulation page
(https://docs.unity.com/en-us/grow/levelplay/sdk/react/regulation-advanced-settings, read by the
draft author on 2026-09-09) says the privacy APIs should be set before init. Whether the SDK
*rejects* the reverse order is undocumented. This task implements the strict order regardless.

`App.tsx:35` calls `initAds()` once at boot. After W0-02, `initAds()` goes through a controller in
`src/ui/adInit.ts` with states `idle | running | ready | failed`, retried on a timer and on
AppState `active`. W0-02 fixes the order inside the function: init, then assign handles, then load.
This task must keep that order and put the consent step in front of it. Four drafts each rewrote
this function (skeptical-14), so this task is the only one that adds consent to it.

This module is CMP-agnostic. A real consent source (a certified CMP) arrives in W7-03. Until then
the gate stays OFF, because this repo has no honest way to decide whether GDPR applies. A locale
guess is not a geography determination.

### Change
1. **`src/ui/consent.ts`, pure TS with no `react-native` import**, so the node jest suite can run it.
   - `type ConsentState = { resolved: boolean; gdprApplies: boolean; personalisedAds: boolean; ccpaOptOut: boolean }`.
   - `encodeConsent(s): number` and `decodeConsent(n): ConsentState` use the bit layout in the P-01
     table above. `decodeConsent(0)` is unresolved.
   - `mayInitAds(s): boolean` is `false` when `!s.resolved`, and `false` when
     `s.gdprApplies && !s.personalisedAds`. Otherwise it is `true`. This is the conservative
     reading: no init at all on a GDPR refusal. Whether non-personalised serving after a refusal
     is lawful is a question for W7-07's legal review. Changing the answer is a one-function change.
   - `privacyCallsFor(s)` returns the ordered call list
     `[['setCOPPA', false], ['setCCPA', s.ccpaOptOut], ['setConsent', s.personalisedAds]]`.
     `setCOPPA(false)` encodes the 13+ age posture from RELEASE.md:89-90, which W7-06 records and
     W7-07 has the owner confirm.
   - `applyPrivacy(s, api)` awaits each call in `privacyCallsFor(s)` order against an injected
     `api` object (`{ setCOPPA, setCCPA, setConsent }`). `ads.tsx` passes the real
     `LevelPlayPrivacySettings` and `LevelPlay` methods.
   - `interface ConsentSource { gather(): Promise<ConsentState>; privacyOptionsRequired(): boolean; showPrivacyOptions(): Promise<ConsentState> }`.
     A comment block above it states what any CMP must supply (W6-06's contribution): a GDPR
     applicability decision from the CMP's own geography check, a consent result, a re-prompt
     entry point, and the TCF storage the mediation layer can read.
   - `lastKnownSource`: a `ConsentSource` that returns `decodeConsent(SaveSystem.consentBits)`
     and never shows UI. It is the fallback while a CMP is unreachable offline.
2. **`SaveSystem`**: `get consentBits(): number` and `setConsentBits(n: number)` on P-01's key. No
   change to `PersistenceKeys` or `resetProgress()`.
3. **`ads.tsx` / `adInit.ts`**, only when `CONSENT_GATE` is true:
   - The controller's `attempt` becomes: `gather()` → persist `encodeConsent` → if
     `!mayInitAds(state)`, return the new outcome `declined` → `applyPrivacy` → `LevelPlay.init` →
     assign handles → load (W0-02's order is unchanged from init onward).
   - `declined` is a terminal state, like `ready`. Neither the timer nor `onAppActive()` retries
     it. A new `consentChanged()` method moves `declined` back to `idle` and starts an attempt.
   - After a successful init, a later consent change calls `applyPrivacy` again immediately. The
     SDK is not torn down. The full effect is stated as "from the next cold start" in the policy
     (W7-05).
   - A throw inside `gather()` or `applyPrivacy()` counts as `failed`, never as consent. Ads stay
     uninitialised and the W0-02 "no ad available" state shows. **No hint or continue is granted.**
4. **Diagnostic fixture source for verification only.** A `ConsentSource` that returns a fixed
   state is compiled in only when `process.env.EXPO_PUBLIC_CONSENT_FIXTURE` is set at build time
   (`granted-eea`, `refused-eea`, `non-eea`). Player builds never set it.
5. `App.tsx` passes the active source to `initAds()`. With the flag OFF, that is none, and today's
   path runs.

### Non-goals
- Any consent UI, CMP dependency or geography logic (W7-03).
- A Settings entry point (W7-04).
- Interstitial pacing (W0-05), and any new ad placement.
- `setGDPRConsents` per-network maps. There is one demand source until W7-12.
- iOS ATT (W8-12).

- **Effort:** L

- **Flag:** `CONSENT_GATE`, default `false`
- **Files:** `package.json`, `package-lock.json`, `app.json`, `src/ui/consent.ts`,

### Context
W7-01 provides the state module, the privacy calls and the `declined` path, but no real source of
consent. The CMP supplies GDPR applicability from its own geography check, shows its own form, and
stores TCF data. The unity-levelplay docs cited in W7-01 say LevelPlay 7.7.0+ reads GDPR consent
from Google UMP and from registered CMPs that support Google Additional Consent. The app runs 9.2.0,
so W7-01's explicit `setConsent` becomes a second channel rather than the only one.

PRODUCT.md:54-55 ("Flow over menus. Open → Play → resume") is broken by any screen before the menu.
The CMP form is a legally required exception. It is limited to players the CMP says are in scope,
and it is the CMP's UI, not ours.

### Change
1. Add the chosen dependency and config plugin, using the owner's ids.
2. `src/ui/cmpConsentSource.ts` implements `ConsentSource`:
   - `gather()` runs the CMP's info update and shows its form if the CMP says one is required,
     then maps the result into `ConsentState`;
   - `privacyOptionsRequired()` returns the CMP's own "privacy options entry point required" status;
   - `showPrivacyOptions()` opens the CMP's re-prompt and returns the new state, and the caller then
     calls `adInit.consentChanged()`;
   - a CMP error (for example offline) falls back to `lastKnownSource`. Unresolved stays unresolved,
     and ads stay uninitialised.
3. `App.tsx`: start `gather()` after save hydration, in parallel with the splash. **Do not block
   reaching the menu on the network.** W0-03's backstop must still reach the menu. If the form
   arrives late it shows over the menu. Ads init waits for the gather result.

### Non-goals

- The Settings entry point (W7-04).
- iOS ATT (W8-12).
- Adding demand sources (W7-12).
